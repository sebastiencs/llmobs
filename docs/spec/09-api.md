# 09 — API surface

All HTTP on one port (`LLMOBS_HTTP_ADDR`, default `0.0.0.0:8080`); OTLP/gRPC on `LLMOBS_GRPC_ADDR` (default `0.0.0.0:4317`); an OTLP/HTTP-only listener on `LLMOBS_OTLP_HTTP_ADDR` (default `0.0.0.0:4318`, serves only `/v1/traces`) for exporters configured with the standard OTel port.

| Prefix | Purpose | Auth |
|---|---|---|
| `/v1/traces` | OTLP/HTTP ingest; follows OTLP (02), not in the OpenAPI document; errors are problem+json (D-G-6) | `sk` (ingest scope) |
| `/api/auth/*` | login, OAuth, invites, reset | none / cookie |
| `/api/v1/*` | REST API (UI + SDK + CLI) | cookie, PAT, or `sk` |
| `/api/public/*` | browser-safe endpoints | `pk` |
| `/mcp` | MCP server (streamable HTTP, `POST` only; not in the OpenAPI document) | PAT (D-H-3) |
| `/healthz`, `/readyz` | probes | none |
| `/` (everything else) | web UI (SPA fallback to `index.html`) | — |

OpenAPI 3.1 generated by `utoipa`, served at `/api/openapi.json`; the TS SDK REST client and the UI API client are generated from it (`openapi-typescript`).

**The contract file (D69).** The generated document is also committed as `crates/server/openapi.json`. A test regenerates it and fails when the committed file differs, so every API change shows up in review. The UI and SDKs generate their clients from this file. Until an operation has a handler, it is declared with utoipa's builder API in `llmobs_server::api::openapi`; when the handler lands, the declaration moves to `#[utoipa::path]` on the handler and the committed file must not change.

**Examples (D72).** `fixtures/api/` holds a small example project (stored spans and scores) and the responses the API returns for it, plus a `manifest.json` mapping operations to response files. The UI uses them as mocks; a test checks them against the Rust response types. See `fixtures/api/README.md`.

## Conventions

- JSON, `snake_case`. IDs: UUIDv7 strings; trace/span IDs as hex, lowercase in responses; requests may use either case.
- Instants are RFC 3339 UTC strings with 9 fractional digits (D64); durations (`*_ns`) are integers.
- Optional scalars are **omitted** when absent; lists and maps in response types are always present (possibly empty). Core types embedded in responses (`Score`, canonical messages) keep their own serde format. In the OpenAPI document an optional field is therefore not nullable. Two exceptions: the message and part fields that keep an explicit source `null` (D65, spec 01), and `next_cursor`, which is always present and `null` on the last page.
- `{project}` path segment accepts a project UUID or slug (`org-slug/project-slug` URL-encoded), or `current` when authenticated with an `sk` key (the key's project).
- Lists under `/api/v1`: `?limit=` (default 50, 1–1000; outside that range → 400; the internal usage export allows 1–10 000, default 1000) + `?cursor=` (opaque); response `{data: [...], next_cursor: string|null}` (`next_cursor` always present).
- Time range params: `from`, `to` (RFC 3339 with any offset, converted to UTC, or integer epoch milliseconds). The range is `[from, to)`; one bound alone leaves the other side open; `from >= to` is `400`.
- Credentials are accepted only in the `Authorization` header or the session cookie, never in a query string (D140).
- Errors: RFC 7807, content type `application/problem+json`: `{type: "about:blank", title, status, code, detail?, errors?: [{field, message, position?: {line, column}}]}`. `code` is a snake_case machine code (`bad_request`, `invalid_filter`, `query_failed`, `query_timeout`, `query_too_large`, `busy`, `unauthorized`, `forbidden`, `sso_required`, `email_not_verified`, `plan_limit`, `not_found`, `method_not_allowed`, `payload_too_large`, `unsupported_media_type`, `range_not_satisfiable`, `conflict`, `rate_limited`, `internal`, `too_many_traces`, `plan_required`, `quota_exceeded`, `owner_not_allowed`). `invalid_filter` (400) covers filter and SQL text; `query_failed` (400) covers execution errors; `query_timeout` and `query_too_large` are 422; `busy` is 503 (D94); `method_not_allowed` is 405; `payload_too_large` is 413; `unsupported_media_type` is 415; `range_not_satisfiable` is 416 (D-G-23); `conflict` is 409; `sso_required`, `email_not_verified` `plan_required` (the org's plan does not include the feature, D-M-16) and `plan_limit` (the org's plan limit is reached; its detail names the limit, D178, D-K-14) are 403; `too_many_traces` (a filter deletion over 100,000 traces, D-M-5) is 422. `quota_exceeded` (the org's monthly units cap, D-P-17) is 402; `owner_not_allowed` (the internal org creation's owner is disabled or an instance admin, D-P-29) is 422. `position` (1-based, in characters) points into the field's value, for DSL and SQL errors. Messages go to the caller and are never logged.
- Idempotency: `Idempotency-Key` header honored on POSTs that create resources (24 h memory).
- Rate limit headers (`RateLimit-*`, IETF draft) on 429.

## Response shapes (observability read API)

Field lists live in the Rust types (`llmobs_server::api`) and the contract file; these are the rules behind them (D70, D73).

- **Payloads are parsed.** Span `input` / `output` are returned as `{format: "messages", value: Message[]}`, `{format: "json", value: <any JSON>}` or `{format: "text", value: string}`. Stored text that does not parse as its declared format degrades instead of failing: `messages` that are not a message array → `json` if the text is JSON, else `text`; `json` that does not parse → `text`. `request_params`, `system_instructions`, `tool_definitions` and event/link `attributes` are returned as parsed JSON (the raw string when it does not parse). `attributes`, `resource_attributes` and `metadata` stay string maps, as stored.
- **Light vs full span.** `SpanSummary` carries the light (**P**) columns of spec 01 except `project_id`, `request_model`, `response_model`, `cost_input`, `cost_output`, plus the computed `duration_ns` and `model`. `SpanDetail` carries every column except `project_id`.
- **Trace detail** = `{trace: TraceSummary, spans: [{depth, detached, span: SpanSummary}], truncated}`. `spans` is a flat list in **pre-order**: roots first, children sorted by `(start_time, span_id)`. A span whose parent is missing (or that sits in a parent cycle) is emitted as a root with `detached: true`. Duplicate span IDs keep the first row. At most 20 000 spans (earliest by `start_time`); `truncated: true` when more exist. The tree is assembled in Rust without recursion.
- **Scores on rows.** `TraceSummary.scores` and `SessionSummary.scores` hold the latest score (greatest `updated_at`, then greatest `score_id`) of each name attached to that trace or session, sorted by name. Full score lists come from `GET /scores`.
- **Session detail** = `{session: SessionSummary, turns: [{trace: TraceSummary, input?, output?}], truncated}`: traces by `start_time`, at most 1 000; `input`/`output` are the root span's payloads (absent when the trace has no root).
- **User detail** = `{user: EndUserSummary, sessions: SessionSummary[]}`: the user's 100 most recent sessions. `EndUserSummary.error_count`, like `SessionSummary.error_count`, is the sum of the traces' `error_count`.
- **Default exclusions** (05) apply to the trace, span, session and user lists, to session/user detail and to metrics; not to trace/span detail or scores. Every endpoint they apply to accepts `include_eval` and `include_experiments`.
- **Saved views** store `state` as an opaque JSON object owned by the UI (its URL search params); the server only checks that it is an object.

## SSE

`text/event-stream`, `event:` names `span`, `trace`, `resync`, `ping` (every 15 s). Data = JSON of the light columns: `span` events carry a `SpanSummary`, `trace` events a `TraceSummary`, `resync` and `ping` an empty object. `span` and `trace` events carry an `id:` that increases over the process's life. Nothing is replayed: a request with `Last-Event-ID`, or a subscriber that fell behind the live bus, first gets `resync`, and the client refetches (D-G-12). Auth by cookie (UI) or bearer. Max 100 concurrent streams per user (per key for an API key); one more is `429` `rate_limited`. Responses send `Cache-Control: no-cache` and `X-Accel-Buffering: no`. Every stream ends when the server shuts down, 15 minutes after it opened, and when its client has not read for 30 s; the span stream also ends after 10 minutes without a span (D-G-34). The client reconnects, which authenticates again, and refetches. A score write sends no event: an open list or trace shows a new score after the trace's next span or a refetch. The trace stream's `search` is checked over the arriving spans' time range: only spans that arrive while the stream is open can match (D-G-33).

## MCP server

Streamable HTTP at `POST /mcp`, stateless, JSON responses, implemented with the `rmcp` crate (D-H-2). There is no stdio bridge in the MVP. Auth: `Authorization: Bearer pat-…` only; a read-only PAT is enough; a cookie or an `sk` key is `403` (D-H-3). Per PAT: 60 requests a minute and 4 at a time, then `429 rate_limited` (D-H-10). Tools (all read-only, D-H-11):

| Tool | Input | Output |
|---|---|---|
| `list_projects` | — | projects the user can read: id, org slug, slug, name, role |
| `get_schema` | `project` | views, columns, types, descriptions (`GET /schema`) |
| `query_sql` | `project, query, params?, from, to, limit?` (1–1,000, default 100), `max_chars?` | columns, rows (JSON), row count, truncated flag, notes. `from`/`to` are required, `from < to`, at most 30 days apart (D-H-9); 30 s timeout |
| `list_saved_views` | `project, kind?` | saved views and SQL queries visible to the user |
| `search_traces` | `project, from, to, view?, filter?, search?, limit?` (1–100, default 20), `include_eval?`, `include_experiments?`, `max_chars?` | compact trace summaries (`view` = saved view id or name; explicit args override it). Window required as for `query_sql` |
| `get_trace` | `project, trace_id, around?, include_payloads=false, max_chars?` | span tree with optional truncated I/O |
| `get_span` | `project, trace_id, span_id, around?, max_chars?` | full span |

`project` is a project UUID or `org-slug/project-slug`. Each result is one text item of compact JSON. Every result is capped at `max_chars` characters (default 20,000, 1,000–100,000); string attribute, metadata and resource-attribute values are cut to 200 characters; a `notes` list names every cut. `query_sql` cuts string cells at 2,000 characters; `get_trace` with `include_payloads` shows the 200-character input/output previews, and `get_span` the full payloads cut to fit `max_chars`. A call whose client disconnects is cancelled and its query dropped (rmcp ignores `notifications/cancelled` in stateless mode, so a cancel without a disconnect runs to the tool's time limit). Argument and query errors are tool results with `isError: true` and `{error: {code, message, position?}}` using the problem codes above.
