# 11 — Web UI

Vite + React + TypeScript, TanStack Router (file routes, typed search params) + TanStack Query + TanStack Table (virtualized with TanStack Virtual), shadcn/ui + Tailwind, Inter for text and JetBrains Mono for IDs, numbers, JSON and code (D127), Recharts through shadcn `chart` for charts (D128), CodeMirror 6 for SQL/DSL editors (with schema-driven autocomplete), Shiki-free JSON viewer (custom collapsible tree). API client: `openapi-typescript` types generated from `crates/server/openapi.json` (committed as `web/src/api/schema.gen.ts`, checked up to date) with `openapi-fetch` + `openapi-react-query` (D75). Lint/format with Biome, tests with Vitest + Testing Library (D74). In development (`pnpm dev`) and in tests, Mock Service Worker answers the API from `fixtures/api/` (D76); `pnpm dev:server` proxies `/api` and `/v1` to a running `llmobs` on port 8080 instead. Mocks are never part of the production build. Built output embedded in the binary by the `llmobs-ui` crate (gzip precompressed, ETags, SPA fallback; D-G-35). Every path that is not a file serves the app, including ids with a dot such as an email address. Dark by default; light and system stay selectable (D127).

**State in the URL:** time range, filter expression, search, sort, columns, selected trace/span and the trace mode are all search params, so every view is shareable and bookmarkable.

Command palette (⌘K): jump to project/page, paste a trace ID to open it.

**Saved views** (traces, spans, sessions, users lists): a "Views" dropdown — save, save as, rename, delete, share with project, set as my default / project default. Loading a view replaces the URL params; a "modified" dot appears when the current state differs from the loaded view. The default view applies when a list page is entered with no search params: when the page loads, or from the sidebar, ⌘K or a `g` shortcut. A change made on the page that leaves the search empty does not re-apply it (D-C-2).

**Signed out (D-L-1).** The root route's `beforeLoad` loads `GET /api/auth/me` for every non-public route. A `401` redirects to `/login?redirect=<path and search>`, or to `/setup` while the server needs setup. A `401` from `/api/v1/*` or from `GET /api/auth/me` during use does the same and clears the query cache. `/login` shows the providers of `GET /api/auth/config` as "Continue with …" buttons, the password form when password login is on, and the message for an OAuth `?error=` code (spec 08).

**Roles (D-L-4).** Settings pages the caller's role cannot use are left out of the settings nav, and show a Forbidden state when opened by URL. Actions above the role are disabled with the reason in a tooltip. **Secrets (D-L-5)** are shown once, in a dialog that closes only on "Done", or on Esc and outside clicks after a Copy.

## Layout and density

A thin top bar and a collapsible left sidebar (D124). The bar shows the product name, the org/project switcher, ⌘K, the theme toggle and the user menu. The sidebar lists the project pages that exist, collapses to icons, and stores that state in localStorage.

Base text is 13 px. Table rows are a fixed 28 px and a single line; previews are truncated and shown in full on hover. IDs and numbers use JetBrains Mono (D127). The theme is dark by default; light and system stay selectable.

Times display in the local time zone. "Show times in UTC" is a user-menu setting stored in localStorage. Hovering a time, and copying it, uses the full RFC 3339 timestamp with nanoseconds (D130).

## Pages

### Filter bar

The text is the truth (D129). One single-line CodeMirror editor holds the filter DSL (spec 05). A client parser splits top-level `AND` conjuncts and recognises simple shapes as editable chips: `column op literal`, `IS [NOT] NULL`, `[NOT] IN (…)`, `@>`, `score('n') op x` and `has_score('n')`. Anything else is a raw chip. A filter with a top-level `OR` is one raw chip, because `AND` binds tighter and splitting it would change its meaning. The `AND` of a `BETWEEN` is never a split point. Click-to-filter puts a filter with a top-level `OR` in parentheses before appending `AND` (D-C-1). The server is the validator: a `400 invalid_filter` underlines the reported position and shows the message, and a broken filter is never applied silently. Autocomplete comes from `GET /schema`. There is no facet sidebar yet.

### Traces (list)

- Header: **saved views menu**, time-range picker (presets `15m` / `1h` / `6h` / `24h` / `7d` / `30d`, default `24h`, plus a custom `from` and `to`; "live" toggle), filter bar, search box, columns menu, toggles "Show evaluation traces" / "Show experiment traces" (off by default).
- Table (virtualized, infinite scroll by cursor): status dot, start time, name, input preview, output preview, duration, tokens, cost, models, session, user, tags, scores (one column per score name present, toggleable), environment.
- Live mode (`live=1`, D134): subscribes to `/traces/stream` when the range is a preset and the sort is `start_time` descending. An absolute range or another sort disables the toggle. The stream gets the list's `filter`, `search`, `include_eval` and `include_experiments` (D-C-5). New rows slide in with a highlight at their start-time place, since traces arrive in the order they finish (a row older than every loaded one waits for paging while more pages remain); a known id is replaced in place. Scrolling away from the top buffers arrivals behind a "N new traces" pill. The buffer keeps the newest 500; past that the pill reads "500+ new traces" and revealing it refetches the first page. A live insert that would grow the first page past 500 rows refetches it instead (D-C-4). A status dot beside the toggle shows connecting, open or retrying, with that word as its name.
- Row click opens the trace in a **resizable split** beside the list and sets `?trace=<id>` (D125). The list keeps its scroll and its selection. `j`/`k` or `↑`/`↓` move between rows and the open trace follows; `Enter` activates the focused row; `Esc` closes the split. The list pane defaults to 40% and the ratio is in localStorage. The same view is the full page at `/:org/:project/traces/:traceId`.
- Bulk actions (add to dataset, delete, export CSV) wait for their API contract (own plan; D123).
- Empty state: onboarding snippets (OTel env vars, Python, TS, Vercel AI SDK) with the project's key prefix.
- URL search params: `range` (or `from` and `to`, RFC 3339, both or neither, `from < to`; the pair wins over `range`); `filter` (DSL text); `search`; `sort` (`TraceSort`, default `start_time`); `order` (`asc` or `desc`, default `desc`); `eval` and `exp` (`1` when on, otherwise off); `cols` (comma-separated column ids); `view` (saved view id); `trace` (32 lowercase hex); `span` (16 lowercase hex); `mode` (`tree` or `transcript`, default `tree`); `live` (`1` when on). An invalid value is dropped.

### Spans (list)

The same table, filter bar and resizable split as Traces, over `GET /spans` (D133). One row per span. There is no spans-first default. URL search params match the traces list except `sort` is `SpanSort` (default `start_time`) and there is no `mode` or `live`: `range` or `from` and `to`, `filter`, `search`, `sort`, `order`, `eval`, `exp`, `cols`, `view`, `trace`, `span`. `?trace=` and `?span=` open that trace with the span selected.

### Trace view

- **Left:** one combined tree and timeline grid (D126). Each virtualized row has an indented name, a kind icon and status, right-aligned duration, tokens and cost, and a bar on a shared time axis. The grid has one set of rows, one selection and one scroll. Error spans are red; rows are collapsible; a search runs within the tree. A **Transcript** toggle (`mode=transcript`) shows the trace's LLM and tool spans in order as one conversation. Each LLM turn shows only the messages not already in the previous LLM call; it waits for that call's detail and, if it cannot be loaded, shows the full input with "Earlier context could not be loaded". The combined grid is the default (`mode=tree`). Live: when the trace ended within the last 10 minutes, or the list is in live mode, the view subscribes to `/traces/:id/stream`, inserts spans in tree order, and shows a Live badge with the connection status and a Stop button. The timeline window follows new spans until the user zooms.
- **Right (selected span):** header (kind, name, model, provider, duration, TTFT, tokens breakdown incl. cache/reasoning, cost, status) and tabs:
  - *Chat* (for `messages` format): system instructions collapsed, messages as bubbles, tool calls/results as cards, reasoning collapsed, images/audio/PDF rendered from `media://` refs, tool definitions in a drawer.
  - *Input / Output*: JSON tree / text / raw toggle; copy buttons; "truncated at ingest" badge when applicable.
  - *Attributes*: metadata, attributes, resource attributes, events (exceptions with stack traces), links.
  - *Scores*: existing scores (source, value, reason, author), read-only until `POST /scores` has a contract (own plan; D123).
- Inside the trace view, the tree and the span detail are a second resizable split (D125). The tree pane defaults to 55% and the ratio is in localStorage.
- Trace header: name, total duration/cost/tokens, session (link), user (link), tags, environment, release. Actions now: copy link, copy ID. Add to dataset, run evaluator on this trace, and delete wait for their API contract (own plan; D123).

### Sessions

List (start, last activity, trace count, user, cost, errors, scores) and detail: a **chat transcript** reconstructed from each trace's root input/output in order, each turn expandable into its trace; session-level scores. The list's URL search params are `range` or `from` and `to`, `filter`, `sort` (`SessionSort`, default `start_time`), `order` (default `desc`), `eval`, `exp`, `cols` and `view`. The session page takes `trace`, `eval` and `exp`. Its split defaults to 55% for the conversation. The annotation form waits for its API contract (own plan; D123).

### Users

End users list (traces, sessions, cost, last seen, errors) and per-user page (their sessions, totals). URL search params are `range` or `from` and `to`, `filter`, `sort` (`UserSort`, default `last_seen`), `order` (default `desc`), `eval`, `exp`, `cols` and `view`. The user page takes `eval` and `exp`. GDPR action "Delete all data of this user" (admins) with confirmation (own plan, once its API contract exists; D123).

### Dashboard

Fixed layout: KPI tiles (traces, error rate, p95 latency, cost, tokens) with comparison to the previous period; charts for traces & errors over time, latency percentiles, cost by model (stacked), tokens by type, TTFT, score averages over time; a "top models by cost" table. Charts use Recharts through shadcn `chart` (D128). Empty buckets are gaps for rates and percentiles. Global filter DSL + time range + group-by (model/environment/release) apply to all widgets. Clicking a chart point opens the trace list filtered to that bucket. Each chart is one keyboard stop: ←/→ move between buckets (announced, and marked with a line), Home/End jump to the ends, Enter opens the bucket's traces (D-C-3). URL search params: `range` or `from` and `to`, `filter`, `group` (`model`, `environment` or `release`), `eval`, `exp`.

### SQL console

CodeMirror editor with schema-aware autocomplete, `⌘↵` to run, result grid (virtualized) with "chart" tab (auto line/bar from the first time or text column and the numeric columns, a line chart with exactly one numeric column is split into one series per value of a second text column; at most 5 series and 1,000 points), export (CSV/Parquet/NDJSON), example queries menu, **saved queries** (private or shared, with parameters), query history (localStorage). Schema browser on the side. Errors shown inline with position. The console has the shared time range picker, and every run and export sends its range as `from`/`to` (D101). The range is part of the URL state and of a saved query's run, like the other views. URL search params: `range` or `from`+`to`, and `view` (a saved query id); the editor draft and parameter values are a per-project localStorage draft; history keeps the last 50 runs per project. Exports download through `fetch` into a Blob (D-H-13).

### Datasets

List; dataset page with version selector, items grid (inline JSON editing in a side panel), add item, import wizard (upload → preview → column mapping → validate → import), export, version history with descriptions, and per-item "source trace" link. (Own plan, once its API contract exists; D123.)

### Experiments

List grouped by dataset; experiment page (aggregates header + items table with scores/latency/cost/output, filters "failed only", "regressions"), compare view (2–4 experiments: aggregate deltas as colored badges, per-item rows side by side with diffs of outputs). Code snippet to run a new experiment. (Own plan, once its API contract exists; D123.)

### Evaluators & online rules

- Evaluators: list; editor with template picker, prompt editor (variables highlighted), output type config, model/connection select, **test panel** (pick a trace/span or paste variables → run → shows score, reason, tokens, cost).
- Online rules: list with status (active / paused: budget / paused: errors), sample rate, spend vs budget; rule editor (evaluator, target, filter DSL with live "N matching in the last 24 h" counter, variable mapping with JSONPath preview on a sample trace, sampling, budget); rule page with recent jobs, failures, score distribution; "backfill" dialog with cost estimate.

(Own plan, once its API contract exists; D123.)

### Alerts

Track K (`docs/plans/k-alerts/`, D-K-13). The project sidebar has "Alerts". The rules list shows each rule's state badge (Firing, OK, No data, Disabled), condition summary, last value and last evaluation. A rule's page shows its condition, last error, an Enabled switch, delete, and the event history with each delivery's status and error. The editor (new and edit) has the metric, window, filter, comparator and threshold (rates typed in percent), minimum samples, channels and reminders, with a preview of the metric over buckets as wide as the window and the threshold line. Project settings → Channels lists channels with their last delivery and has create/edit (write-only secrets), delete and "Send test". A `plan_limit` answer shows its detail with an upgrade line.

### Settings

A settings sidebar replaces the project sidebar on settings routes: a Back link, a Project group (on project routes) and an Organization group (D-L-6). The project sidebar has a "Settings" entry at its bottom, and the org home has a "Settings" button.

- **Project** (track L): General (name; retention in days or "keep forever", with a warning that lowering it drops older partitions right away), API keys (create a secret or a public key with scopes and expiry, shown once with the snippets, revoke; admins only), Members (each org member's org role, override and effective role; overrides for org members and viewers only). Score definitions, channels and the **Data** tab (GDPR deletions by user ID or by filter with a preview count, deletion history and status, delete project) have their own plans once their API contract exists (D123).
- **Org** (track L): General (name; the slug is fixed), Members (role changes, remove, leave) and invites (email and role; the accept link is shown to copy, and is the only way to share it when SMTP is off). "New organization" is in the org switcher and "New project" on the org home. LLM connections (track I): list for every member; add, edit, delete and test for admins (D-I-4); custom model prices, usage (daily spans/bytes/judge cost charts) and delete org have their own plans (D123).
- **Account** (`/account`, track L): name, password (an optional current password, D-L-12), personal access tokens (create with read or read-write scope and expiry, shown once, revoke).
- **Instance admin** (`/admin`, track L): users (add with a one-hour password link, make or remove admin, disable or enable, create a reset link) and the read-only instance settings with "Send test email".

## Quality bar

- Trace list first paint < 1 s on 1B spans (server targets in D23); trace view usable with 10 000 spans (virtualized tree). Verified by bounded rendered-row counts in tests (D132): under 60 rows on a 5 000-trace list, under 80 rows in a fully expanded 10 000-span tree, at most 50 transcript detail requests before "Load more", and under 100 rows in a 20 000-key JSON tree.
- Keyboard: `/` focus search, `j/k` move in lists, `esc` close the split, `?` shortcuts help.
- Accessibility: shadcn/Radix primitives, focus management in the splits and in drawers, color not the only status signal.
- No external network calls from the UI (fonts and icons bundled), so air-gapped installs work.
