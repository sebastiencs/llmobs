### Permission rules (pure functions, unit-tested)

```rust
/// What the access check decided. `Hidden` answers 404, `Forbidden` 403.
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
enum Decision {
    Allowed,
    Hidden,
    Forbidden,
}

/// D-H-6 for PATCH.
fn may_update(row: &SavedViewRow, user: Uuid, role: Role, changes: &SavedViewChanges) -> Decision

/// D-H-6 for DELETE.
fn may_delete(row: &SavedViewRow, user: Uuid, role: Role) -> Decision
```

`may_update`, in order:
1. `!visible_to(row, Viewer::User(user))` → `Hidden`.
2. The caller owns the row (`row.owner_user_id == Some(user)`): when every field of `changes` is `None` (an empty PATCH) → `Allowed` (the store writes nothing). Otherwise let `shared_after = changes.shared.unwrap_or(row.shared)`. If `shared_after && role < Role::Member` → `Forbidden` (D-H-6: sharing, or any change to a view that stays shared, needs member; a viewer may keep private views and unshare their own). Otherwise `Allowed`.
3. Not the owner (so the row is shared): `Allowed` only when `role == Role::Admin`, `changes.shared == Some(false)`, and `name`, `state` and `is_default` are all `None` (moderation is unsharing only). Otherwise `Forbidden` — including an empty PATCH.

A shared view without an owner (its owner was deleted) can be deleted by an admin; unsharing it returns H2's `MetaError::Conflict(UNSHARE_ORPHAN)`, which becomes `409 conflict` with detail `the view has no owner; delete it instead` (D-H-6).

`may_delete`, in order: not visible → `Hidden`; owner → `Allowed`; `role == Role::Admin && row.shared` → `Allowed`; otherwise `Forbidden`.

Create (inline in `create_view`): `body.shared && role < Role::Member` → `Forbidden`. Nothing else is restricted: any role may create private views and private defaults.

### Handler bodies

`list_views`:
1. `let cursor = checked_cursor(params.cursor.as_deref())?;`
2. `store::list_visible(state.meta.reader(), access.project.id, viewer(&principal), params.kind, page_limit(params.limit), cursor.as_deref()).await?` — `page_limit` is `crate::routes::read::page_limit` (`Limit` → `usize`).
3. Answer `Page { data: page.rows.into_iter().map(SavedView::from).collect(), next_cursor: page.next_cursor }`.

`create_view`:
1. `let user = principal::session_user(&principal)?.id;` then `let role = role_of(&access)?;`.
2. `let name = checked_name(&body.name)?; checked_state(&body.state)?;`
3. `if body.shared && role < Role::Member { return Err(forbidden()); }`
4. Copy what the closure needs into locals first (`let project_id = access.project.id; let now = state.clock.now_ns();`; `user` and `role` are already `Copy`), so the `move` closure owns them. `state.meta.write(move |conn| Box::pin(async move { store::insert_view(conn, NewSavedView { project_id, kind: body.kind, name, state: body.state, owner_user_id: user, shared: body.shared, is_default: body.is_default }, now).await }))` with `now = state.clock.now_ns()`. `MetaError::Conflict("too many saved views")` becomes `409 conflict` through the existing `From<MetaError> for ApiError`.
5. `tracing::info!(project_id = %access.project.id, view_id = %row.id, kind = kind_str(row.kind), "saved view created");` (all three log lines of this module are `info`).
6. Answer 201 with `SavedView::from(row)`.

`update_view`:
1. `user`, `role` as above.
2. Validate before touching the database: `name` (when `Some`) through `checked_name`, `state` (when `Some`) through `checked_state`. Build `SavedViewChanges { name, state, shared: body.shared, is_default: body.is_default }`.
3. In one `state.meta.write`: `view_by_id(conn, project, path.id)`; `None` → return `Ok(Outcome::Missing)`; `may_update(&row, user, role, &changes)`: `Hidden` → `Ok(Outcome::Missing)`, `Forbidden` → `Ok(Outcome::Forbidden)`, `Allowed` → `update_view(conn, project, path.id, changes, now)` and `Ok(Outcome::Done(row))` (a `None` from `update_view` cannot happen inside the same transaction; map it to `Outcome::Missing` anyway). `Outcome` is a private enum `{ Missing, Forbidden, Done(SavedViewRow) }`. Returning `Ok` for the refusals is fine: nothing was written, so the commit is empty.
4. `Missing` → `ApiError::NotFound`; `Forbidden` → `forbidden()`; `Done(row)` → log `"saved view updated"` (same fields as create) and answer 200 with `SavedView::from(row)`.

Note the name clash: the handler is `update_view` and the store function is `meta::saved_views::update_view`. Import the store module as `use crate::meta::saved_views::{self as store, …}` and call `store::update_view`, `store::delete_view`, `store::insert_view`, `store::view_by_id`.

`delete_view`: same shape: `view_by_id`, `may_delete`, then `store::delete_view`; answer `StatusCode::NO_CONTENT`, log `"saved view deleted"` with `project_id` and `view_id`.

Never log `name` or `state`.

### Order of checks (tests rely on it)

Access layer (401/403/404) → path parameters (`{id}` not a UUID: 400 `invalid path parameter id`) → body extraction (400/413/415) → field validation (400) → role and ownership (403/404) → store (409). So a viewer posting `{"kind":"traces","name":"","state":{},"shared":true}` gets 400 for `name`, not 403.

Size limits: the whole body is at most 128 KiB (413 above it) and `state`, re-serialized compactly with `serde_json::to_vec`, at most 65,536 bytes. A body under 128 KiB whose `state` is over 64 KiB only because of escaping is still a 400 on `state`; an over-escaped body above 128 KiB is a 413, which is accepted.
