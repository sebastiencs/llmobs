# H9 — `llmobs query`

One commit: `cli: add llmobs query`.

Adds the CLI's HTTP client (server URL and token resolution, problem errors, project path segments), a shared table renderer, and `llmobs query`, which runs `POST /api/v1/projects/{project}/sql` and prints a table or JSON, or streams a CSV, NDJSON or Parquet export. H10 reuses the client, the renderer and the test helpers for `traces` and `projects`.

## Step 0 — the server config ignores the CLI's variables

`ServerConfig::load` turns every `LLMOBS_*` environment variable into a config key and rejects unknown keys, so a shell that exports `LLMOBS_URL`, `LLMOBS_TOKEN` or `LLMOBS_PROJECT` for the CLI would break `llmobs serve` (spec 12 lists these three as CLI-only). In `crates/server/src/config.rs`, change `is_filtered` to:

```rust
/// `LLMOBS_CONFIG` and the CLI's own variables (D-H-12) are not config keys.
fn is_filtered(name: &str) -> bool {
    ["LLMOBS_CONFIG", "LLMOBS_URL", "LLMOBS_TOKEN", "LLMOBS_PROJECT"]
        .iter()
        .any(|filtered| name.eq_ignore_ascii_case(filtered))
        || alias_key(name).is_some()
}
```

Add to `config.rs`'s test module, next to the test that calls `load_from(None, &[("LLMOBS_FOO", "1")])`:

```rust
#[test]
fn cli_variables_are_not_config_keys() {
    let config = load_from(
        None,
        &[
            ("LLMOBS_URL", "http://127.0.0.1:8080"),
            ("LLMOBS_TOKEN", "pat-llmobs-EXAMPLE0EXAMPLE0EXAMPLE0EXAMPLE0"),
            ("llmobs_project", "acme/app"),
        ],
    );
    assert!(config.is_ok());
}
```

## Step 2 — `output.rs`

```rust
//! Terminal output shared by the query, traces and projects commands.

/// Where a command reads and writes. `main` passes the real stdin, stdout and stderr; tests
/// pass byte buffers.
pub(crate) struct Io<'a> {
    /// Results.
    pub(crate) out: &'a mut dyn Write,
    /// Notes (row counts, truncation, next-page cursors). Never results.
    pub(crate) err: &'a mut dyn Write,
    /// The statement for `query --file -`.
    pub(crate) input: &'a mut dyn Read,
    /// Whether stdout is a terminal. Parquet refuses to write binary to one.
    pub(crate) stdout_is_terminal: bool,
}

/// One table column.
pub(crate) struct Column {
    /// Header text.
    pub(crate) name: String,
    /// Right-align the cells (numbers).
    pub(crate) right: bool,
}

/// Most characters a cell shows. Longer text keeps its first 59 characters plus `…`.
pub(crate) const CELL_MAX_CHARS: usize = 60;

pub(crate) fn render_table(out: &mut dyn Write, columns: &[Column], rows: &[Vec<String>]) -> io::Result<()>;
/// Every `char` for which `char::is_control()` is true becomes one space. Nothing else changes.
pub(crate) fn clean(text: &str) -> String;
pub(crate) fn json_cell(value: &serde_json::Value) -> String;
pub(crate) fn format_time(ns: i64) -> String;      // moved unchanged from main.rs
pub(crate) fn write_rows_note(err: &mut dyn Write, rows: usize, more: Option<&str>) -> io::Result<()>;
```

**`clean`** replaces each `char` with `char::is_control()` true (C0 and C1 controls: tab, newline, carriage return, ESC, …) with `' '`. `is_control` does not cover Unicode format characters such as bidi overrides (U+202E); they pass through unchanged, which is accepted.

**`json_cell`** turns one JSON value into cell text:

| Value | Text |
|---|---|
| `null` | `NULL` |
| `true` / `false` | `true` / `false` |
| number | `number.to_string()` (serde_json's formatting: `15`, `0.000024`) |
| string | the string itself |
| array or object | `serde_json::to_string(value)` (compact; nested values stay compact JSON) |

**`render_table`** writes, in this order:

1. Each cell and each header is passed through `clean`. Then, when the cleaned text has more than `CELL_MAX_CHARS` characters (`chars().count()`), it becomes its first 59 characters followed by `…` (U+2026), so it is exactly 60 characters. This cut lives only in `render_table`.
2. A column's width is the largest `chars().count()` among its cleaned header and cleaned cells.
3. The header line: each header padded to its column's width (right-aligned when `right`, else left-aligned), columns joined by two spaces.
4. The rule line: for each column, `-` repeated to its width, joined by two spaces.
5. One line per row, padded and joined the same way.
6. Every line has its trailing spaces removed (`trim_end_matches(' ')`) and ends with `\n`.

Padding counts characters, not bytes: pad with `width - text.chars().count()` spaces. With no rows, the header and rule lines are still written. With no columns, nothing is written (not even a newline).

Example (`name` left, `total_tokens` right):

```
name  total_tokens
----  ------------
chat            15
```

**`write_rows_note`** writes one line to `err`: `1 row` when `rows == 1`, otherwise `<rows> rows`; when `more` is `Some(text)`, `; ` and `text` follow. Then `\n`.

**`format_time`**: move the function from `main.rs` unchanged and make it `pub(crate)`. `main.rs`'s `write_table` and `listed_user` call `output::format_time`.

`Token`'s value parser comes from `FromStr` (clap uses it for `Option<Token>` automatically). `Target`, `ConnectionArgs` and `Cli` derive `Debug`; the token inside prints as `Token(***)`. Never write the token anywhere except the `Authorization` header.

### `resolve_target`

`args.url` and `args.token` already hold the flag or, failing that, the environment variable (clap's `env`). A URL that is empty or all whitespace, and a token that is empty after trimming, count as absent. The URL is passed through `credentials::normalize_server_url`.

| `url` | `token` | Result |
|---|---|---|
| set | set | `Target { server: url, token }`; `credentials` is not called |
| absent | set | error `--token needs --url (or LLMOBS_URL)`; `credentials` is not called |
| set | absent | `credentials::load(&credentials()?)?`; the entry for the normalized URL, else error ``no saved token for <url>; run `llmobs login --url <url>` `` |
| absent | absent | `credentials::load(&credentials()?)?`; 0 servers: error ``not logged in; run `llmobs login --url <URL>` or set LLMOBS_URL and LLMOBS_TOKEN``; 1 server: that server and its token; 2 or more: error `more than one saved server; pass --url` |

Then, whatever the row: the flag or `LLMOBS_URL` URL is checked with `credentials::check_server_url` before anything else, and row 4's saved server before its token is read. A URL with embedded credentials is refused with `the server URL must not contain credentials` before any message can print the URL (rows 3 and 4's `no saved token for <url>` included), whatever its source: the flag, `LLMOBS_URL`, a saved key in the credentials file, or `llmobs login --url` (checked before anything is printed, verified or saved). A URL that does not parse, or whose scheme is not `http`/`https` (ASCII case-insensitive; `HTTPS://h` is accepted), is refused with `--url must start with http:// or https://`. A saved token that is empty after trimming counts as absent: rows 3 and 4 answer `no saved token for <url>; run \`llmobs login --url <url>\``. A saved token becomes a `Token` through `Token::from_str` (trimmed). The token is not checked for the `pat-` shape: an `sk` key works for `query` and `traces` on its own project.

### `project_segment`

Percent-encode every byte of `project.as_bytes()` that is not an ASCII letter, digit, `-`, `.`, `_` or `~` as `%` plus two uppercase hex digits. `acme/support-bot` → `acme%2Fsupport-bot` (spec 09: the slug form is `org-slug/project-slug`, URL-encoded); a UUID is unchanged.

### `ApiClient`

- `new` builds:

  ```rust
  reqwest::Client::builder()
      .connect_timeout(Duration::from_secs(10))
      .read_timeout(Duration::from_secs(300))
      .redirect(reqwest::redirect::Policy::none())
      .user_agent(concat!("llmobs-cli/", env!("CARGO_PKG_VERSION")))
      .build()
  ```

  with error context `building the http client`. No overall client timeout. `read_timeout` (300 s) fails a response whose body stays idle for 5 minutes, so a stalled export cannot hang the CLI forever; it is a constant and is not tested. Redirects are not followed: a `3xx` is a non-2xx status like any other (so a bearer token is never replayed to another host).
- Every request goes to `format!("{}{path}", target.server)` with `Authorization: Bearer <token.expose()>`, and its body through `RequestBuilder::json` (which sets `Content-Type: application/json`).
- `post_json` adds `Accept: application/json` and `RequestBuilder::timeout(timeout)`, which covers the whole exchange.
- `post_stream` adds `Accept: <accept>` and sets no `RequestBuilder::timeout`. It wraps `request.send()` in `tokio::time::timeout(header_timeout, …)`; when that expires, the error is `could not reach <server>: no answer within <n>s`, where `<n>` is `header_timeout.as_secs()` (rounded down). Once headers have arrived, reading the body has no client-side time limit: the server's own query timeout ends a slow export (D-H-8).
- A send error (connect refused, DNS, TLS, `post_json`'s timeout) is `anyhow::Error::new(error).context(format!("could not reach {server}"))`. reqwest's error text holds the URL and never the header.
- A non-2xx status reads at most 64 KiB of the body with `chunk()` (bytes past 64 KiB are dropped; a read error ends the read and keeps what was read), bounded by `read_timeout` and, for `post_json` and `get_json`, by the request's timeout, then returns `problem_error(status, &body, server)`.
- `post_json` parses a 2xx body with `serde_json::from_slice`; a parse failure is `the server sent an invalid response`. Reading the 2xx body can itself fail (the server closes the connection early); that error carries the context `reading the answer from <server>`.

The timeouts (`connect_timeout`, `read_timeout`, the header wait) are constants or derived from flags and are not tested.

If clippy reports `large_futures` on an `async` call in the CLI, wrap that future in `Box::pin(...)`; add no `#[allow]`.

### `problem_error`

1. Status `401`: `` the server rejected the token; run `llmobs login --url <server>` ``.
2. Otherwise, when `body` parses as `llmobs_server::api::common::Problem`: the first line is `<title> (<code>): <detail>`, or `<title> (<code>)` without a detail. `<title>` is the body's `title`. `<code>` is the snake_case wire value: `serde_json::to_value(problem.code)` as a string (for example `invalid_filter`). Then, for each entry of `errors`, a new line `  <field>: <message>`, followed by ` (line <line>, column <column>)` when `position` is set.
3. Otherwise: `the server answered <status>`, where `<status>` is `reqwest::StatusCode`'s `Display` (`502 Bad Gateway`, `302 Found`).

Every server-supplied string (`title`, `detail`, each `field` and `message`) is passed through `output::clean` first, so a hostile server cannot send terminal escape sequences. Build the error with `anyhow::anyhow!("{text}")`. `main` prints `{error:#}` and exits 1, as for every other command.

Using `llmobs_server::api::common::Problem` (rather than a CLI copy) keeps the CLI on the contract type the server serializes; `llmobs-server` is already a dependency.


In this order:

1. **Statement.** `args.sql`, or the file's contents (`std::fs::read_to_string`, error context `reading <path>`), or, when the path is exactly `-`, all of `streams.input` (`Read::read_to_string`, context `reading stdin`). A statement that is empty after `trim()` is the error `the query is empty`. The statement is sent as read, not trimmed.
2. **Export and limit.** When the format is `csv`, `ndjson` or `parquet` and `args.limit` is set: error `--limit applies to the table and json formats; exports stop at 10,000,000 rows`.
3. **Parquet to a terminal.** Format `parquet`, no `--output`, and `streams.stdout_is_terminal`: error `refusing to write Parquet to a terminal; pass --output FILE`.
4. **Window.** `--from`/`--to` are sent as given (the server checks RFC 3339 and `from < to`). `--since` becomes `since_window(text, now)?`. Neither: no window.
5. **Parameters.** `parameters(&statement, &args.params)?` (below).
6. **Target.** `client::resolve_target(&args.connection, credentials)?`, then `ApiClient::new(target)?`.
7. **Request.** Path `format!("/api/v1/projects/{}/sql", client::project_segment(&args.project))`. Body:

   ```rust
   #[derive(Serialize)]
   struct SqlBody<'a> {
       query: &'a str,
       #[serde(skip_serializing_if = "serde_json::Map::is_empty")]
       params: serde_json::Map<String, serde_json::Value>,
       #[serde(skip_serializing_if = "Option::is_none")]
       from: Option<String>,
       #[serde(skip_serializing_if = "Option::is_none")]
       to: Option<String>,
       #[serde(skip_serializing_if = "Option::is_none")]
       limit: Option<u32>,
       #[serde(skip_serializing_if = "Option::is_none")]
       timeout_ms: Option<u32>,
   }
   ```

   `--timeout-ms` only sets the body's `timeout_ms`, the server's query limit. The client waits `args.timeout_ms.unwrap_or(60_000)` milliseconds plus 30 seconds: for the whole exchange in table and json (`post_json`'s `timeout`), and for the response headers only in exports (`post_stream`'s `header_timeout`).
8. **Table and json.** `post_json`, then `serde_json::from_value::<SqlResult>(value)` (error `the server sent an invalid response`):

   ```rust
   /// `SqlQueryResult` (README § Contracts). The CLI keeps its own copy: it needs only these
   /// fields, and the server tests below check it against the real server.
   #[derive(Deserialize)]
   struct SqlResult { columns: Vec<SqlColumn>, rows: Vec<serde_json::Map<String, serde_json::Value>>, truncated: bool }
   /// `SqlColumnInfo`. The Arrow `type` is not needed by the CLI, so it is not read.
   #[derive(Deserialize)]
   struct SqlColumn { name: String }
   ```

   Do not add `deny_unknown_fields` to either struct. Build the whole output in a `Vec<u8>` first:

   - **table**: one `Column` per entry of `columns`, in order; `right: true` when at least one row has a JSON number in that column and every non-null value in it is a number (all-null or no rows: left). Cells are `json_cell(row.get(name).unwrap_or(&Value::Null))`. Render into a `Vec<u8>` with `render_table`.
   - **json**: `serde_json::to_writer_pretty(&mut buffer, &rows)?` (the `rows` array only), then `\n`.

   Then `write_all` the buffer to the destination (step 10), then on `streams.err` `write_rows_note(err, rows.len(), more)` where `more` is `Some("more rows matched; raise --limit or export with --format csv, ndjson or parquet")` when `truncated`, else `None`.
9. **Exports.** `accept(args.format)` gives the `Accept` value:

   ```rust
   /// `Accept` of an export format; `None` for table and json.
   fn accept(format: QueryFormat) -> Option<&'static str>
   ```

   `Csv` → `Some("text/csv")`, `Ndjson` → `Some("application/x-ndjson")`, `Parquet` → `Some("application/vnd.apache.parquet")`, `Table` and `Json` → `None`. Call `post_stream` with it. Once it returns the 2xx response, open the destination (step 10), then `while let Some(chunk) = response.chunk().await.transpose()` writes each chunk. A chunk error is the error `the export stopped before its end; the output is incomplete` (with `--output`, `PATH` is left as it was) (the server aborts the body without its final chunk when the query fails mid-way, D-H-8). No note is written to `streams.err` for exports.
10. **Destination.** It is opened only after the server answered 2xx. With `--output PATH`: create `PATH` plus the suffix `.part` (`let mut part = path.as_os_str().to_owned(); part.push(".part");`) with `std::fs::File::create` (context `creating <path>`; mode from the process umask, like any created file), write everything, `flush`, `sync_all`, then `std::fs::rename` it to `PATH` (context `writing <path>`). On any error after the `.part` file was created, remove it (`std::fs::remove_file`, ignoring its error) before returning the error. So a failed request or a cut export never creates, truncates or replaces `PATH`. Without `--output`: write to `streams.out`. The row note always goes to `streams.err`.
11. **Broken pipe.** `run` flushes `streams.out` after its last write. When writing or flushing `streams.out` fails with `io::ErrorKind::BrokenPipe` (for example `llmobs query … | head -1`), `run` returns `Ok(())` at once: nothing more is written, no note, exit status 0. Rust ignores `SIGPIPE`, so the write returns that error. Other write errors are errors.

### `parameters`

```rust
/// The five `{name:Type}` types of spec 05 § Parameters.
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
enum ParamType {
    String,
    Int,
    Float,
    Bool,
    Timestamp,
}

/// `{name:Type}` placeholders of `statement`, first occurrence of each name.
fn placeholder_types(statement: &str) -> BTreeMap<String, ParamType>;

fn parameters(statement: &str, raw: &[String]) -> anyhow::Result<serde_json::Map<String, serde_json::Value>>;
```

**`placeholder_types`** follows spec 05: placeholders are recognized only outside string literals and comments. The server finds them in sqlparser's token stream (`crates/storage/src/sql/params.rs`, `GenericDialect` of sqlparser 0.62): five **consecutive** tokens `{`, an unquoted word, `:`, an unquoted word, `}` — no whitespace or comment may sit between them. The scan mirrors that tokenizer for what matters here; the server stays the validator. It reads the characters of `statement` left to right, keeping whether the previous character was an identifier part (below):

- `'` starts a string literal that ends at the next `'` not followed by another `'` (`''` is an escaped quote; a backslash is an ordinary character). Skip it whole. An unterminated literal ends the scan.
- `E` or `e` immediately followed by `'`, when the previous character is not an identifier part, starts an escape string: inside it a `\` escapes the next character (skip both), `''` is an escaped quote, and the next other `'` ends it. Skip it whole.
- `"` or `` ` `` starts a quoted identifier that ends at the next same quote not followed by another one (doubling escapes it). Skip it whole: a quoted word is not a placeholder word for the server either.
- `$$` starts a dollar-quoted string that ends at the next `$$`. `$` followed by a tag (an identifier start, then identifier parts other than `$`) and `$` starts `$tag$ … $tag$`, ending at the next `$tag$`. Skip either whole; an unterminated one ends the scan. Any other `$` is an ordinary character.
- `--` starts a comment that ends after the next `\n` (or at the end); skip it.
- `/*` starts a comment that ends after the next `*/` (no nesting; unterminated ends the scan); skip it.
- `{`: try to read, with **nothing** between the parts, a name, `:`, a type word, `}`. A name or type word is an identifier start (`char::is_alphabetic()`, `_`, `#` or `@`) followed by identifier parts (`char::is_alphabetic()`, an ASCII digit, `@`, `$`, `#` or `_`). The type word matches `string`, `int`, `float`, `bool`, `timestamp` ignoring ASCII case. When every part matches and the name is not yet in the map, insert it. Whether it matched or not, continue with the character after that `{`.
- Any other character is skipped; remember whether it is an identifier part (for the `E'` rule).

An unknown type, two types for one name, a missing value or whitespace inside the braces are the server's `400`.

**`parameters`**: for each `raw` entry, split at the **first** `=` (`a=b=c` gives name `a`, value `b=c`). No `=`, or an empty name: error `--param expects NAME=VALUE`. A name given twice: error `parameter <name> is given twice`. The value is converted by the name's placeholder type:

| Type | JSON sent | Invalid value |
|---|---|---|
| `String` | the string | — |
| `Timestamp` | when the value is an integer text (below): that `i64`, epoch milliseconds (so `t=2026` means 2026 ms after the epoch); otherwise the string (RFC 3339, checked by the server) | an integer text outside `i64`: `parameter <name> must be an RFC 3339 timestamp or epoch milliseconds` |
| `Int` | an integer text parsed as `i64` | not an integer text, or outside `i64`: `parameter <name> must be an integer` |
| `Float` | `f64` parsed with `str::parse`, sent through `serde_json::Number::from_f64`; NaN or infinite is invalid (`nan`, `inf`, `1e400`) | `parameter <name> must be a number` |
| `Bool` | `true` for `true`, `false` for `false` (exact, lowercase) | `parameter <name> must be true or false` |
| not a placeholder | the string (the server answers `400 unknown parameter <name>`) | — |

An **integer text** is an optional `-` followed by one or more ASCII digits and nothing else; check it yourself before `str::parse::<i64>` (which would also accept `+5`), so `+5` and `5.0` are not integers. The `--param` help says: `A parameter value; repeat for each parameter. Int and Timestamp values that are all digits are sent as integers (Timestamp: epoch milliseconds).` The error messages contain the parameter name only, never its value.

### `since_window`

```rust
/// `[now - duration, now)` as two RFC 3339 strings with nanoseconds and `Z`.
pub(crate) fn since_window(text: &str, now: chrono::DateTime<chrono::Utc>) -> anyhow::Result<(String, String)>;
```

`pub(crate)`: H10 uses it. `text` is one or more ASCII digits not starting with `0`, then one unit: `s`, `m`, `h` or `d` (1, 60, 3,600 or 86,400 seconds). Compute without panicking: the number with `str::parse::<i64>`, times the unit with `i64::checked_mul`, then `chrono::TimeDelta::try_seconds`, then `now.checked_sub_signed(delta)`. Any malformed text and any `None`/`Err` along the way is the error `--since expects a duration such as 30m, 24h or 7d`. `from` is the result, `to` is `now`, both formatted with `to_rfc3339_opts(SecondsFormat::Nanos, true)`.

### Canned server

```rust
/// One request the canned server received.
#[derive(Debug, Clone)]
pub(crate) struct Recorded {
    /// The request target: path and query, as sent.
    pub(crate) target: String,
    /// The request line and headers, as sent.
    pub(crate) head: String,
    /// The body, as UTF-8 (lossy).
    pub(crate) body: String,
}

/// A local HTTP server that answers with fixed bytes. Dropping it stops it.
pub(crate) struct Canned {
    pub(crate) url: String,
    recorded: Arc<Mutex<Vec<Recorded>>>,   // std::sync
    task: tokio::task::JoinHandle<()>,
}

impl Canned {
    /// Answers one connection per entry of `responses`, in order, writing each entry's bytes
    /// verbatim. Connections past the last entry wait until the server is dropped.
    pub(crate) async fn raw(responses: Vec<Vec<u8>>) -> Self;
    /// `raw` with `HTTP/1.1 <status> X\r\nContent-Type: application/json\r\nContent-Length: <len>\r\nConnection: close\r\n\r\n<body>` for each entry.
    pub(crate) async fn json(responses: Vec<(u16, String)>) -> Self;
    /// The requests received so far, in order.
    pub(crate) fn recorded(&self) -> Vec<Recorded>;
}

impl Drop for Canned {
    fn drop(&mut self) { self.task.abort(); }
}
```

`raw` binds `tokio::net::TcpListener` on `127.0.0.1:0`, sets `url = format!("http://{addr}")`, and spawns the task. For each response: `accept()`; read until the bytes contain `\r\n\r\n`; the head is everything before it; the target is the second space-separated word of its first line; when a `content-length` header is present (case-insensitive name), read that many more body bytes; push the `Recorded` (lock, push, unlock) **before** writing the response; write the response bytes; `shutdown()` the socket. After the last response the task keeps accepting and drops each connection without answering. A request is therefore recorded before the CLI can see its answer, so a test reads `recorded()` right after the command returns. `Connection: close` makes reqwest open a new connection per request; reqwest prints the status from its own table, so the reason phrase `X` never shows. Lock poisoning in a test helper may `unwrap`.

Every `pub(crate)` item of this module is used by this phase's tests, so no `dead_code` warning appears.
