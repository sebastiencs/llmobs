## API

| Operation | Call | Fixture |
|---|---|---|
| `get_me` | `GET /api/auth/me` | `static/me.json`: Ada, `is_instance_admin: true` |
| `list_admin_users` | `GET /api/v1/admin/users?limit=50&cursor=` | `static/admin-users.json`: Ada (admin) and Bob |
| `patch_admin_user` | `PATCH /api/v1/admin/users/{id}`, body `{disabled?}` or `{is_instance_admin?}` → `200 AdminUser` | none; tests override it |
| `post_admin_user_reset_link` | `POST /api/v1/admin/users/{id}/reset-link`, no body → `200 {url}` | none; tests override it |
| `post_admin_user` | `POST /api/v1/admin/users`, body `{email, name?, is_instance_admin?}` → `201 {user, reset_url}` | `static/admin-user-created.json` (a POST example; the mocks never serve it, so tests override it) |

These are the server's answers (`crates/server/src/routes/admin.rs`, `crates/server/src/meta/users.rs`):

| Case | Status | `detail` |
|---|---|---|
| `PATCH` on your own id | 400 `bad_request` | `cannot change your own account` |
| Disabling the last enabled owner of an org | 409 `conflict` | `the user is the last owner of an org` |
| Leaving no enabled instance admin | 409 `conflict` | `the instance would have no active administrator` |
| Reset link for a disabled user | 409 `conflict` | `the user is disabled` |
| Creating an existing email | 409 `conflict` | `email already registered` |
| Unknown id | 404 `not_found` | — |
| Invalid email or name on create | 400 `bad_request` with `errors[0].field` `email` or `name` | — |

### 2. Error messages — `web/src/components/admin/messages.ts`

```ts
import { problemMessage, problemOf } from "@/api/problem";

/** Text for a failed PATCH or reset-link call on one account. */
export function adminUserError(error: unknown): string {
  const problem = problemOf(error);
  switch (problem?.detail) {
    case "cannot change your own account":
      return "You can't change your own account.";
    case "the user is the last owner of an org":
      return "This user is the last owner of an organization. Make someone else an owner first.";
    case "the instance would have no active administrator":
      return "This would leave the instance without an active admin.";
    case "the user is disabled":
      return "This account is disabled. Enable it first.";
    default:
      break;
  }
  if (problem?.status === 404) {
    return "This user no longer exists.";
  }
  return problemMessage(error, "The change failed. Try again.");
}
```

`messages.test.ts` (imports `expect` and `it` from `vitest`, `adminUserError` from `./messages`) has one `it` per branch. Build each problem inline as a complete object, because `isProblem` needs `type`, `title`, `status` and `code`:
- `{ type: "about:blank", title: "Bad Request", status: 400, code: "bad_request", detail: "cannot change your own account" }` gives "You can't change your own account.";
- `{ type: "about:blank", title: "Conflict", status: 409, code: "conflict", detail }` for each of `the user is the last owner of an org`, `the instance would have no active administrator` and `the user is disabled` gives the text of step 2's `switch`;
- `{ type: "about:blank", title: "Not Found", status: 404, code: "not_found" }` gives "This user no longer exists.";
- `{ type: "about:blank", title: "Internal Server Error", status: 500, code: "internal", detail: "boom" }` gives "boom";
- `new Error("x")` gives "The change failed. Try again.".

### 5. Users page — `web/src/routes/admin/users.tsx`

`createFileRoute("/admin/users")({ component: AdminUsersPage })`. It has no search params.

The component:

1. Reads `me` with `$api.useSuspenseQuery("get", "/api/auth/me")`.
2. Lists users with:

   ```ts
   $api.useInfiniteQuery("get", "/api/v1/admin/users", adminUsersInit(), {
     pageParamName: "cursor",
     initialPageParam: null,
     getNextPageParam: (page) => page.next_cursor ?? undefined,
   })
   ```

3. Sets up the mutations:
   - `const patch = $api.useMutation("patch", "/api/v1/admin/users/{id}")`;
   - `const resetLink = $api.useMutation("post", "/api/v1/admin/users/{id}/reset-link", { gcTime: 0 })`. Its response is a password link, a secret (D-L-5).
4. Keeps this state (`useState` each; `Schema` from `@/api/types`):
   - `actionError: string | undefined`;
   - `disableTarget: Schema<"AdminUser"> | undefined`: the user the disable dialog is about. It is set when the dialog opens and **never cleared on close**, so the title does not flash "Disable ?" while Radix animates the dialog out; the next `onDisable` replaces it;
   - `disableOpen: boolean`, `false`: whether the disable dialog is open;
   - `disableError: string | undefined`;
   - `resetFor: Schema<"AdminUser"> | undefined`, the user whose link is being shown;
   - `addOpen: boolean`;
   - `created: { email: string; url: string } | undefined`.

**Header.** A row with `<h2 className="text-lg font-medium">Users</h2>`, a flex spacer, and a `Button` labelled "Add user" with a `UserPlus` icon. The button sets `addOpen = true`.

**States:**
- Loading (`isPending`): four `Skeleton className="h-8 w-full"`.
- Error: `throw users.error`, as `web/src/routes/$org/index.tsx` does.
- Empty (no rows on any page): `<EmptyState icon={Users} title="No users" />`. This cannot happen against a real server, but render it anyway.
- Data: the table below, then a "Load more" button while `hasNextPage`, exactly like the org home (outline, spinner while `isFetchingNextPage`).

**`<FormError message={actionError} />`** sits right above the table. Every action clears `actionError` when it starts.

**Table:** `<Table aria-label="Users">`. The columns, in order:

| Header | Cell |
|---|---|
| Email | the email. When `user.id === me.user.id`, add `<Badge variant="outline">You</Badge>` after it. |
| Name | `user.name`, or `—` (`text-muted-foreground`) when absent |
| Status | badges in this order, each only when it applies: `Admin` (`secondary`) when `is_instance_admin`; `Disabled` (`destructive`) when `disabled`; `Unverified` (`outline`) when `!email_verified`; `SSO only` (`outline`) when `!has_password`. Put them in a `flex flex-wrap gap-1`. With none, render nothing. |
| Providers | `providers.join(", ")` in `font-mono text-xs`, or `—` when empty |
| Created | `<TimeText value={user.created_at} style="datetime" />` |
| (actions, header text `<span className="sr-only">Actions</span>`) | `<UserActions …/>` (step 6) |

Each row is `<TableRow key={user.id}>`.

**One action at a time.** `patch` and `resetLink` are shared by every row, and TanStack Query runs the `onSuccess` / `onError` given to `mutate(vars, { … })` only for the latest call (README § Pitfalls). So every row's Actions button is disabled while **either** mutation is pending: `const busy = patch.isPending || resetLink.isPending`, passed to every row as `pending={busy}`. The per-call callbacks below are then always the latest call's.

**Actions handlers** (passed to `UserActions`):
- `onToggleAdmin(user)`:
  - sets `actionError = undefined`;
  - calls `patch.mutate({ params: { path: { id: user.id } }, body: { is_instance_admin: !user.is_instance_admin } }, { onSuccess: invalidate, onError: (error) => setActionError(adminUserError(error)) })`.
- `onEnable(user)`: the same, with body `{ disabled: false }`.
- `onDisable(user)`: sets `actionError = undefined`, `disableError = undefined`, `disableTarget = user` and `disableOpen = true`.
- `onResetLink(user)`:
  - sets `actionError = undefined` and `resetFor = user`;
  - calls `resetLink.mutate({ params: { path: { id: user.id } } }, { onError: (error) => { setResetFor(undefined); setActionError(adminUserError(error)); } })`.
- `invalidate` is `() => void queryClient.invalidateQueries({ queryKey: adminUsersKey() })`, with `queryClient` from `useQueryClient()`.

**Disable confirmation:** a `ConfirmDialog` with:
- `open={disableOpen}`;
- `onOpenChange={(open) => { if (!open) { setDisableOpen(false); setDisableError(undefined); } }}`;
- `title={`Disable ${disableTarget?.email ?? ""}?`}` (`disableTarget` is always set while the dialog is open or closing);
- `description="They are signed out at once and can't sign in until an admin enables the account. Their personal access tokens stop working."`;
- `confirmLabel="Disable"`, `destructive`, `pending={patch.isPending}`;
- `error={disableError}`.

`onConfirm` calls `patch.mutate({ params: { path: { id: disableTarget.id } }, body: { disabled: true } }, …)` (return early when `disableTarget` is undefined, which cannot happen while the dialog is open):
- `onSuccess`: `setDisableOpen(false)` and `invalidate()`;
- `onError`: `setDisableError(adminUserError(error))`.

`onConfirm` first sets `disableError = undefined`. `onDisable` clears it when the dialog opens and `onOpenChange(false)` when it closes. The dialog is modal, so no other action can start while it is open.

**Reset link dialog:** L2's `SecretDialog`, rendered only while the link exists (the pattern of `01-foundations.md` L2 step 4):

```tsx
{resetFor && resetLink.data ? (
  <SecretDialog
    open
    title={`Reset link for ${resetFor.email}`}
    secret={resetLink.data.url}
    description="This link sets a new password and works for one hour."
    onDone={() => {
      setResetFor(undefined);
      resetLink.reset();
    }}
  />
) : null}
```

The dialog always adds "Copy it now. You won't see it again." That stays true for this link: the page never shows it again, and "Create reset link" makes a new one.

**Add user:** `<AddUserDialog open={addOpen} onOpenChange={setAddOpen} onCreated={(email, url) => { setAddOpen(false); setCreated({ email, url }); invalidate(); }} />` (step 7). Then:

```tsx
{created ? (
  <SecretDialog
    open
    title="User created"
    secret={created.url}
    description={`Send this link to ${created.email}. It sets their password and works for one hour.`}
    onDone={() => setCreated(undefined)}
  />
) : null}
```

### 2. The handlers — `web/src/mocks/writes.ts`

Write one function per operation, keyed by `operationId`:

```ts
type Respond = (input: { body: Record<string, unknown>; params: Record<string, string> }) => Response;
const RESPONSES: Record<string, Respond> = { … };
```

The body is read once, in the handler below, and passed in: a request body can be read only once.

Then build the handlers:

```ts
export const writeHandlers: HttpHandler[] = WRITE_OPERATIONS.map((operation) => {
  const respond = RESPONSES[operation.operationId];
  if (!respond) {
    throw new Error(`writes: no response for ${operation.operationId}`);
  }
  const path = operation.path.replace(/\{([^}]+)\}/g, ":$1");
  return http[operation.method](path, async ({ request, params }) =>
    respond({ body: (await readJson(request)) ?? {}, params: stringParams(params) }),
  );
});
```

`stringParams` is the copy of `pathParamsOf`; `readJson` the copy from `saved-views.ts`. A request without a JSON body (a DELETE, logout) gets `{}`.

`/api/v1/me/tokens/current` and `/api/v1/me/tokens/:id` both match `DELETE …/current`. Both answer `204`, so the order does not matter.
