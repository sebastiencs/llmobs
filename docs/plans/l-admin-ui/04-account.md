**Rules that apply to every component and test in this file** (README § Conventions and § Pitfalls):
- **Hooks come first.** Every hook call (`useState`, `useRef`, `useQuery`, `useSuspenseQuery`, `useMutation`, `useQueryClient`, `useNavigate`, …) comes before the first `if (…) return …` or `if (…) throw …` of its component. - **Every `validateSearch` returns all its keys**, set to `undefined` when the value is rejected.
- **Proving that no request was made.** For a write (POST, PATCH, PUT, DELETE), installing no handler is enough: an unhandled write fails the test. For a GET, the fixtures answer silently, so install a counting handler and assert it was called 0 times.
- Test wrapper components are defined at module level; elements that appear after a request are found with `await screen.findBy…`.

## Why the top bar needs a change

`OrgSwitcher`, `ProjectSwitcher` and `CommandPalette` each call `useParams({ from: "/$org" })`. That call throws on a route that is not under `/$org`, such as `/account` or `/admin/users`. The org-scoped controls are therefore shown only when a `/$org` match exists. Outside an org, the top bar shows the product link, the theme toggle and the user menu. The ⌘K palette and its `g` shortcuts are not available outside an org, because all of their entries are org or project pages.

`export function ProfileForm()`.

**State:**
- `name`: starts as `me.user.name ?? ""`;

**Render:** a `<form>` with `noValidate`, `className="flex max-w-md flex-col gap-4"` and `aria-labelledby="profile-heading"`, containing:
1. `TextField`: id `profile-email`, label "Email", type `email`, value `me.user.email`, `readOnly`, `onChange={() => {}}` (L1's `TextField` requires `onChange`; the empty function is fine for a read-only field and passes Biome's recommended rules), description "Your email can't be changed here."
2. `TextField`: id `profile-name`, label "Display name (optional)", value `name`, `maxLength={100}`, `autoComplete="name"`, description "Leave empty to show your email instead.", `error={fieldErrors(save.error).name}`, `disabled={save.isPending}`. Its `onChange` sets `name` and sets `saved` to `false`.
3. `<FormError message={save.error && !fieldErrors(save.error).name ? problemMessage(save.error, "Could not save your name. Try again.") : undefined} />`
4. `<FormSuccess message={saved ? "Name saved." : undefined} />`
5. `<div><SubmitButton pending={save.isPending}>Save name</SubmitButton></div>`

**Submit** (`onSubmit`):
1. `event.preventDefault()`, then `setSaved(false)`.
2. `const trimmed = name.trim();`
3. Call `save.mutate({ body: trimmed.length > 0 ? { name: trimmed } : {} }, { onSuccess: … })`. An absent `name` clears the display name (spec 09: "A missing `name` and JSON null both clear the display name").
4. `onSuccess`: `setName(trimmed)`, `setSaved(true)`, `void queryClient.invalidateQueries({ queryKey: meQuery.queryKey })`.

Nothing else happens on error: the field error or the `FormError` shows it.

### 6. `web/src/components/account/password-form.tsx` (new)

`export function PasswordForm()`.

**Data:** `const change = $api.useMutation("post", "/api/v1/me/password");` — operation `post_me_password`, body `ChangePasswordRequest`, response `204`.

**State:**
- `current`: string, `""`;
- `next`: string, `""` (the new password);
- `confirm`: string, `""`;
- `clientErrors`: `PasswordProblems` (from `@/components/auth/password-fields`), `{}`;
- `done`: boolean, `false`.

Every one of the three fields' `onChange` sets its value, clears `clientErrors` (`setClientErrors({})`) and sets `done` to `false`. Pass `onPasswordChange={(value) => { setNext(value); setClientErrors({}); setDone(false); }}` and the same shape for `onConfirmChange` and the current field.

**Errors from the server** (`crates/server/src/routes/me.rs` `change_password`):
- a wrong current password is `403` `forbidden` with no `detail` and no `errors`. A `403` also means password login is disabled on the server; the same message is shown, because the page cannot tell the two apart;
- a missing current password on an account that has one is `400` with `errors: [{ field: "current_password", message: "current password is required" }]` (D-L-12); a current password on an account that has none is `400` on the same field;
- a weak new password is `400` on `new_password`;
- `429` is the rate limit.

Compute once per render:

```ts
const problem = problemOf(change.error);
const serverFields = fieldErrors(change.error);
const currentError =
  serverFields.current_password ?? (problem?.status === 403 ? "Current password is incorrect." : undefined);
```

**Render:** a `<form>` with `noValidate`, `className="flex max-w-md flex-col gap-4"` and `aria-labelledby="password-heading"`, containing:
1. `TextField`: id `password-current`, label "Current password (optional)", type `password`, `autoComplete="current-password"`, value `current`, description "Leave empty if you have never set a password (single sign-on accounts).", `error={currentError}`, `disabled={change.isPending}`. This is D-L-12.
2. `<PasswordFields password={next} confirm={confirm} onPasswordChange={…} onConfirmChange={…} passwordLabel="New password" passwordError={clientErrors.password ?? serverFields.new_password} confirmError={clientErrors.confirm} disabled={change.isPending} />`. Its inputs have the ids `password` and `password_confirm` and the labels "New password" and "Confirm password" (L4).
3. `<FormError message={formError} />`, where `formError` is:
   - `undefined` when `change.error` is not set, or when `currentError` or `serverFields.new_password` is set;
   - `RATE_LIMITED` (from `@/components/auth/messages`, "Too many attempts. Wait a minute and try again.") when `problem?.status === 429`;
   - otherwise `problemMessage(change.error, "Could not change your password. Try again.")`.
4. `<FormSuccess message={done ? "Password changed. Your other sessions and personal access tokens were signed out." : undefined} />`
5. `<div><SubmitButton pending={change.isPending}>Change password</SubmitButton></div>`

**Submit:**
1. `event.preventDefault()`, then `setDone(false)` and `change.reset()` (so a stale server error never sits next to a new client error).
2. `const problems = passwordProblems(next, confirm); setClientErrors(problems);`. If `problems` has any key, send nothing.
3. `change.mutate({ body: current.length > 0 ? { current_password: current, new_password: next } : { new_password: next } }, { onSuccess })`. `current` is sent untrimmed, because passwords are never trimmed.
4. `onSuccess`: clear `current` and both new-password fields, then `setDone(true)`.

The current session stays signed in. The server revokes only the other sessions and the personal access tokens. Do not navigate.

### 2. `web/src/components/account/token-format.ts` (new)

These are pure helpers.

```ts
import type { Schema } from "@/api/types";

export type TokenAccess = "read" | "read-write";
export type TokenExpiry = "never" | "30" | "90" | "365";

export const EXPIRY_OPTIONS: readonly { value: TokenExpiry; label: string }[] = [
  { value: "30", label: "30 days" },
  { value: "90", label: "90 days" },
  { value: "365", label: "1 year" },
  { value: "never", label: "Never" },
];

/** `["read"]` → "Read only"; `["read", "write"]` (any order) → "Read and write". */
export function accessLabel(scopes: readonly Schema<"PersonalTokenScope">[]): string {
  return scopes.includes("write") ? "Read and write" : "Read only";
}

export function scopesFor(access: TokenAccess): Schema<"PersonalTokenScope">[] {
  return access === "read-write" ? ["read", "write"] : ["read"];
}

/** RFC 3339 instant `days` after `now` (ms since epoch), or undefined for "never". */
export function expiresAt(expiry: TokenExpiry, now: number): string | undefined {
  if (expiry === "never") {
    return undefined;
  }
  return new Date(now + Number(expiry) * 86_400_000).toISOString();
}
```

### 2. `web/src/lib/cli-auth.ts` (new)

```ts
export type CliAuthSearch = { port?: string; state?: string; host?: string };

export type CliRequest = { port: number; state: string; host?: string };

const PORT = /^[1-9]\d{3,4}$/;
const STATE = /^[A-Za-z0-9_-]{1,256}$/;
/** D-L-9: at least one non-digit, so the router's JSON parsing (README § Conventions, Search params) never turns it into a number. */
const HAS_NON_DIGIT = /[^0-9]/;
const HOST = /^[A-Za-z0-9.-]{1,64}$/;

/**
 * The three values exactly as they appear in the raw query string.
 * TanStack Router JSON-parses search values (README § Conventions, Search params):
 * values like `port=54321` would come back as numbers and `host=1e3` as `1000`, and the router re-serialises
 * `location.searchStr` too. The route therefore reads `useRouter().history.location.search`, the raw string.
 */
export function cliAuthSearchFrom(searchStr: string): CliAuthSearch {
  const params = new URLSearchParams(searchStr);
  const out: CliAuthSearch = {};
  for (const key of ["port", "state", "host"] as const) {
    const value = params.get(key);
    if (value !== null) {
      out[key] = value;
    }
  }
  return out;
}

/** D-L-9. Any invalid value makes the whole request invalid. */
export function parseCliRequest(search: CliAuthSearch): CliRequest | undefined {
  const { port, state, host } = search;
  if (port === undefined || !PORT.test(port)) {
    return undefined;
  }
  const portNumber = Number(port);
  if (portNumber < 1024 || portNumber > 65535) {
    return undefined;
  }
  if (state === undefined || !STATE.test(state) || !HAS_NON_DIGIT.test(state)) {
    return undefined;
  }
  if (host !== undefined && !HOST.test(host)) {
    return undefined;
  }
  return host === undefined ? { port: portNumber, state } : { port: portNumber, state, host };
}

export function cliTokenName(request: CliRequest): string {
  return request.host ? `CLI on ${request.host}` : "CLI";
}

/** The CLI's callback. The host is always 127.0.0.1; only the port comes from the link (spec 08). */
export function cliCallbackUrl(
  request: CliRequest,
  result: { token: string } | { error: "access_denied" },
): string {
  const url = new URL(`http://127.0.0.1:${request.port}/callback`);
  if ("token" in result) {
    url.searchParams.set("token", result.token);
  } else {
    url.searchParams.set("error", result.error);
  }
  url.searchParams.set("state", request.state);
  return url.toString();
}
```
