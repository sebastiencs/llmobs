Implementation plan, split into small sub-phases. Each sub-phase is done by one agent in one go and ends with `just check` green and one commit.

## Why this step exists

Wave 1 starts several parallel tracks. The UI tracks (trace list, trace view, sessions, users, dashboard, saved views) need a working web app before any handler exists: tooling, a typed API client generated from the contract, mocks that serve `fixtures/api/`, routing, the app shell and the conventions for pages and tests. The SDK tracks need packages with their toolchains and the configuration layer that every later SDK feature reads.

This step delivers both, with one real page (the org home) proving the whole chain: generated types → client → mocks → router → page → tests.

## Scope

**In:**
- A pnpm workspace at the repo root, Biome, `.node-version`.
- `web/`: Vite + React + TypeScript, Tailwind + shadcn/ui, TanStack Router + Query, generated API types, `openapi-fetch` client, MSW mocks from `fixtures/api/`, theme (light/dark/system), bundled font, app shell, routes `/` and `/:org`, the org home page (projects list), not-found and error states, tests, production-build check.

**Out:**
- Embedding `web/dist` in the binary with `memory-serve` (the server has no HTTP layer yet; the track that adds axum does it).

- CI (step 6).

AGENTS.md applies to TypeScript and Python too: no placeholders (no empty pages, nav entries to pages that don't exist, stub modules or unused dependencies), no compatibility layers, no unnecessary abstractions, every behaviour change has tests.

## S3 — Mocks from `fixtures/api`

**Goal:** every manifest entry is served by MSW in `pnpm dev` and in Vitest, never in the production build.

### Dependencies

`msw` (dev).

### `src/mocks/manifest.ts`

- Imports `../../../fixtures/api/manifest.json` and `../../../crates/server/openapi.json` (JSON imports). Allow the repo root in `server.fs.allow` in `vite.config.ts`.
- Loads response bodies with `import.meta.glob("../../../fixtures/api/{static,responses}/**/*.json", { eager: true, import: "default" })` and media with `import.meta.glob("../../../fixtures/api/media/*.png", { eager: true, query: "?inline", import: "default" })` (a `data:` URL, decoded to bytes once). If `?inline` does not yield a data URL under Vitest, find the closest working equivalent and report it; the media test below must pass in both environments.
- Builds `operations: MockOperation[]`, one per `operation_id` that has manifest entries:
  ```ts
  interface MockOperation {
    operationId: string;
    method: "get";                 // every manifest entry is a GET (checked)
    mswPath: string;               // "/api/v1/projects/:project/traces/:trace_id"
    entries: MockEntry[];
  }
  interface MockEntry {
    pathParams: Record<string, string>;
    query: Record<string, string>;
    status: number;
    contentType: string;
    body: unknown | Uint8Array;    // parsed JSON or media bytes
  }
  ```
  `method` and the path come from `openapi.json` by `operationId`; `{name}` becomes `:name`. Throw (at import time — this is dev/test code) if a manifest `operation_id` is missing from the document, is not a GET, or a `file` has no loaded body.

### `src/mocks/handlers.ts`

`export const handlers: HttpHandler[]` built from `operations`. Matching for a request:
1. Candidate entries: every manifest key in `pathParams` equals the request's path param. Params not in the entry (`project`, and `org` when absent) match anything (fixtures README: mocks match any project).
2. Among candidates, keep those whose `query` is a subset of the request's query (same key, same string value). Pick the one with the most query keys. Two winners with the same count is a manifest ambiguity → throw.
3. No match → `404` with `Content-Type: application/problem+json` and body `{"type":"about:blank","title":"Not Found","status":404,"code":"not_found"}` (what the real API returns for an unknown trace, session, user, org or file).
4. JSON entries: `HttpResponse.json(body, { status, headers: { "Content-Type": contentType } })`. Media: the bytes with the entry's content type. `Range` is ignored (always 200, full body).

Only GET operations with manifest entries get handlers. Writes (saved views) and the SSE streams have none: the tracks that build those features add in-memory handlers next to their code.

MSW tries handlers in registration order. Sort them so a path with more literal segments comes first (then by path), so a future `/traces/stream` handler wins over `/traces/:trace_id`. Today no two mocked paths overlap; the sort is tested with a synthetic list.

### `src/mocks/browser.ts` and `src/mocks/node.ts`

- `browser.ts`: `export const worker = setupWorker(...handlers)`.
- `node.ts`: `export const server = setupServer(...handlers)`.
- `msw init msw --save` writes `web/msw/mockServiceWorker.js` (commit it). A tiny Vite plugin in `vite.config.ts` (`apply: "serve"`) serves that file at `/mockServiceWorker.js` from `configureServer` middleware, so it never lands in `dist/` (the `public/` directory is copied into builds).

### Dev modes

- `main.tsx`, before rendering:
  ```ts
  if (import.meta.env.DEV && import.meta.env.MODE !== "server") {
    const { worker } = await import("./mocks/browser");
    await worker.start({ onUnhandledRequest: "warn", quiet: false });
  }
  ```
  `import.meta.env.DEV` is statically `false` in production builds, so the branch and the dynamic import are dropped.
- Script `dev:server`: `vite --mode server`. In that mode `vite.config.ts` sets `server.proxy` for `/api` and `/v1` to `http://localhost:8080` (D51). In the default mode no proxy is set.
- `just web-dev-server`: `pnpm --dir web run dev:server`.

### `scripts/check-dist.mjs`

Run after `vite build` in the `check` script (`pnpm build && node scripts/check-dist.mjs`). Fails (exit 1, listing every problem) when:
- `dist/index.html` is missing;
- any file in `dist/` is named `mockServiceWorker.js`;
- any file in `dist/` contains `ada@example.com`, `fixtures/api` or `setupWorker` (fixture data or MSW in the bundle);
- `dist/index.html` references an `http://` or `https://` URL (fonts and scripts must be local).

### Tests

`test/setup.ts` now starts the node server: `beforeAll(() => server.listen({ onUnhandledRequest: "error" }))`, `afterEach(() => server.resetHandlers())`, `afterAll(() => server.close())`.

`mocks/manifest.test.ts`:
1. Every manifest entry is a GET of an operation in `openapi.json`.
2. For **every** manifest entry: build the URL from the openapi path (`project` → `acme%2Fsupport-bot`, other params from `pathParams`, query from `query`), `fetch` it, and check status, `Content-Type` and body (deep-equal to the file's JSON, or byte-equal for media).
3. The media body's SHA-256 (WebCrypto `crypto.subtle.digest`) equals its file name.
4. Query selection: `list_traces` with `include_eval=true&limit=10` → `traces-include-eval.json`; with `limit=10` only → `traces.json`; with `include_eval=false` → `traces.json`.
5. Unknown trace id → 404 problem with `code: "not_found"`; `list_projects` for org `nope` → 404 problem.
6. Handler order: for synthetic operations `/a/:id` and `/a/stream`, the literal path sorts first.
7. The committed `msw/mockServiceWorker.js` carries the installed `msw` version (the worker file embeds `PACKAGE_VERSION`; compare with `msw/package.json`'s version). Fails after an `msw` upgrade until `msw init` is re-run.

## S4 — Router, app shell and org home

**Goal:** `/` takes a signed-in user to their org; `/:org` shows the shell and the org's projects. This is the pattern every Wave 1 page follows.

### Dependencies

`@tanstack/react-router`; dev `@tanstack/router-plugin` (and `@tanstack/router-cli` if you need it for `tsr generate`). shadcn: `add table skeleton avatar badge`.

### Router setup

- `vite.config.ts`: `tanstackRouter({ target: "react", autoCodeSplitting: true })` **before** `react()`.
- `routeTree.gen.ts` is generated and git-ignored. Make `typecheck` and `test` work from a clean checkout: prefix them with route generation (`tsr generate`, or whatever the router docs recommend for your version), and say which in the report.
- `src/router.tsx`:
  ```ts
  export interface RouterContext { queryClient: QueryClient }
  export function createAppRouter(options: { queryClient: QueryClient; history?: RouterHistory }): AppRouter
  ```
  with `defaultPreload: "intent"`, `defaultPreloadStaleTime: 0` (TanStack Query owns caching), `defaultNotFoundComponent: NotFound`, `defaultErrorComponent: ErrorState`, `scrollRestoration: true`. Register the type (`declare module "@tanstack/react-router" { interface Register { router: AppRouter } }`).
- `main.tsx`: `QueryClientProvider` (from `createAppQueryClient()`) → `ThemeProvider` → `RouterProvider`.

### Routes

| File | URL | Behaviour |
|---|---|---|
| `routes/__root.tsx` | — | `createRootRouteWithContext<RouterContext>()`; renders `<Outlet/>`. |
| `routes/index.tsx` | `/` | `loader`: `queryClient.ensureQueryData($api.queryOptions("get", "/api/auth/me"))`. If `orgs` is non-empty, `throw redirect({ to: "/$org", params: { org: orgs[0].slug } })` (first org in API order). Otherwise renders `EmptyState`: "You are not a member of any organization yet." (Org creation and invites come with the auth/settings tracks.) |
| `routes/$org/route.tsx` | `/:org` layout | `loader`: ensure `/me`; if no org has `slug === params.org`, `throw notFound()`. Renders the shell: `AppHeader` and `<main className="…"><Outlet/></main>`. |
| `routes/$org/index.tsx` | `/:org` | The org home page below. |

> ## Lifecycle
>
> - **Exit.** Python: `init()` registers an `atexit` hook that calls `shutdown()`. > - **`flush()`** blocks (Python) or resolves (TS) when pending spans and scores are exported or the export timeout expires. **`shutdown()`** flushes, then stops the exporters; it is idempotent, and spans and scores after it are dropped.
> - **Buffers.** Spans go through the OTel `BatchSpanProcessor` with its default queue size; when it is full, new spans are dropped (OTel behaviour).
