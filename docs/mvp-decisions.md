# llmobs — MVP definition

Working name: **llmobs** (real name to be decided later).
Competitor research: `research/competitors.md`.

## MVP scope at a glance

**Ingestion**
- OTLP over HTTP + gRPC; normalizes OTel GenAI semconv, OpenInference, OpenLLMetry, Vercel AI SDK attributes.
- 10 MiB HTTP / 32 MiB gRPC request limit (413); attributes >8 MiB truncated with a marker.
- Server-side extraction of base64 media → content-addressed (SHA-256, per project) blobs in object storage.
- Cost + tokens from a price table (LiteLLM import + per-project custom prices), incl. cache/reasoning tokens.

**Storage**
- Single binary, single machine. DataFusion + Parquet (own layout, manifest in SQLite), local disk or S3.
- WAL + in-memory Arrow buffer → spans queryable within seconds (live view).
- Tombstone deletes, physical removal at compaction; retention by dropping time partitions.

**UI** (React/TS, embedded in the binary)
- Trace list (visual filter builder + SQL-like filter DSL + full-text scan), trace tree/timeline with live updates, chat rendering of LLM spans, media rendering, sessions view, fixed metrics dashboard.
- SQL console over the user's project data.
- Saved views (list pages) and saved SQL queries, private or shared.
- Scores and human annotation on spans/traces/sessions.
- Datasets (versioned, CSV/JSONL import, add-from-trace), experiment results/comparison.
- Online judge rules, alert rules, settings (orgs, projects, members, API keys, LLM connections).

**Evaluation**
- Online LLM-as-judge on traces and spans: filter + sampling + cost cap; built-in templates (hallucination, relevance, toxicity, correctness vs expected, custom).
- Built-in Rust checks (exact, contains, regex, JSON valid, JSON schema, Levenshtein); webhook evaluator.
- Experiments run client-side via SDK `evaluate(dataset, task, scorers)`.

**Alerts**: error rate, cost over window, p95 latency, judge score under threshold → Slack webhook, webhook, email.

**Access**
- Orgs → projects; roles owner/admin/member/viewer (+ per-project override).
- Email/password (argon2id), GitHub/Google OAuth, generic OIDC. No SAML in v1.
- API keys: `pk-` (write-only, browser feedback) / `sk-`; SHA-256 hashed; optional expiry; ingest-only scope.
- Public end-user feedback endpoint.

**Interfaces**: REST + OpenAPI, MCP server, CLI, Python + TypeScript SDKs (thin layer over OpenTelemetry).

**GDPR**: delete by user_id, by trace/filter, by project, by org; per-project retention; cascades to all derived data.

**Packaging**: binary, Docker image, docker-compose, minimal Helm chart; documented snapshot backup.

| D82 | Cost | **Cost with missing unit prices.** When a price row matches, every token count that is present and greater than 0 needs a unit price. `reasoning` falls back to `output`; nothing else falls back. If a needed unit price is null, the part it belongs to (`cost_input` or `cost_output`) is null, and so is `cost_total`. The other part is still computed, and `cost_source` stays `computed`. Embedding spans use the input price only: `cost_output` is null and `cost_total = cost_input`. |
| D83 | Storage catalog | `llmobs-storage` keeps its catalog in its own `<data_dir>/catalog.db` (data files, WAL checkpoints, media index, its side of deletions), with its own migrations and writer, `synchronous=FULL`. `meta.db` belongs to the server and keeps deletion requests with their cascades; it hands them to storage idempotently by deletion id. Storage never reads `meta.db`; retention and project lifecycle reach it through its API. Backups copy both files together (spec 03 §4, 04, 12). |
| D84 | Small files | Files stay per `(project, partition day)`. A flush writes its files in parallel and commits them in one catalog transaction; compaction's size-ratio rule bounds small files (spec 03 §2, §5). |
| D85 | Span time bounds | Normalization rejects spans whose `start_time` is before 2000-01-01, before `ingest_time − retention_days`, or more than 1 day after `ingest_time`; they count in `rejected_spans` (spec 02 rule 15). |
| D86 | Trace anchor | Spans and trace partials are partitioned by the trace's anchor day, the partition day of its first partial, so a trace crossing midnight lives in one day for retention and compaction. A row's anchor day is at most one day from its own date; day pruning uses one day of slack (spec 03 § Trace anchor). Kept after the trace-list benchmark: rebuilding the map at startup read 4 MB in 51 ms on 5M traces (`docs/research/storage/traces-benchmark.md`). |
| D87 | Storage durability | A file is durable (fsynced file and directory on local disk; completed upload on S3) before a catalog row makes it active; outputs are recorded in `staged_objects` before they are written. WAL write errors are final. Catalog commits are serialized through one committer and compare-and-set their inputs and `flushed_seq`. Obsolete files are deleted once no read snapshot references them and a grace period has passed (spec 03 §1, §2, §4, §5). |
| D88 | Derived traces | Every `traces` file is computed from a recorded set of `spans` files. Compaction and deletion rewrites recompute it whenever they replace those `spans` files, so duplicate spans stop inflating trace totals once compacted (spec 01, 03 §3). |
| D89 | Query layering | `llmobs-storage`'s providers expose the stored Arrow schemas (binary IDs, `project_id`) and are not registered by name. The query layer (track A2: `filter/` and `sql/` modules) builds the user-facing views of spec 05 over them: hex IDs, hidden `project_id`, `sessions`, the hex-to-binary literal rewrite and default exclusions. Storage semantics stay in the providers (memtable + files, tombstones, trace merging, score last-writer-wins). |
| D90 | Config format | Each crate's settings are a nested section (`[storage]` with `wal`, `flush`, `memtable`, `compaction`, `query`, `gc`, `deletion`, `anchor` sub-tables). Sizes are strings with a binary unit (`"256MiB"`), durations strings with a unit (`"120s"`); parsed with `bytesize` and `humantime-serde`. Env overrides follow the path (`LLMOBS_STORAGE__WAL__SYNC`). |
| D91 | Query context | A2 builds the DataFusion `SessionContext`. `Storage::query` returns a `ProjectQuery`: the three raw providers (`spans`, `traces`, `scores`, stored schemas, D89), the per-query `RuntimeEnv` (memory pool, spill directory), `target_partitions` and the physical optimizer rules to append (D153). `QueryContext::new` builds the session from that: DataFusion's built-in scalar, nested, aggregate and window functions, with no table functions and no higher-order functions; no `information_schema`, no URL tables, recursive CTEs off; parser recursion limit 50, source spans collected; the hex-ID optimizer rule; only the views registered (spec 05, 03 §6). |
| D92 | Read queries | The queries behind the read endpoints live in A2 (`llmobs_storage::reads`): trace, span, session, user and score lists with sort and cursor; trace, span, session and user detail; latest scores per row; dashboard metrics. They return Arrow batches with documented columns, or plain structs for metrics. The server maps them to API types and does HTTP. Cursors are encoded and checked by A2 (spec 05, 09). |
| D93 | SQLite views | `experiment_items` and `dataset_items` belong to the server: their schema, their rows (a `MemTable` of at most 1M rows built per query) and their column catalog. The server registers them through `QueryContext::register_sqlite_view`. A2's sandbox only knows their names (spec 05). |
| D94 | Query errors | Filter, SQL and execution error messages go back to the caller (capped at 2 KiB) and are never logged; logs carry the error kind, text lengths and the duration. Codes: `invalid_filter` (400) for filter and SQL text; `query_failed` (400) for execution errors; `query_timeout` (422); `query_too_large` (422) for the memory cap; `busy` (503) when admission control refuses the query (spec 05, 09). |
| D95 | Input limits | Filter DSL: at most 4 KiB and 128 operator tokens. SQL: at most 64 KiB and 512 operator tokens. Parser recursion limit 50. Checked on the token stream before parsing, because a left-deep chain of operators is not bounded by the parser recursion limit and planning about 3,000 `OR` terms overflows a 2 MiB stack (spec 05). |
| D96 | SQL sandbox | One statement: a query, or a plain `EXPLAIN` of a query (no `ANALYZE`, no `VERBOSE`). Table references are unqualified names of registered views or of CTEs in scope. No table functions. Recursive CTEs are disabled. `score`, `score_label` and `has_score` are not available in SQL (D97). DataFusion's `SQLOptions` (no DDL, DML or statements) is checked again on the plan (spec 05). |
| D97 | Score functions | `score(name)`, `score_label(name)` and `has_score(name)` exist in the filter DSL only, on the `traces`, `spans` and `sessions` views. For each target they use the latest live score of that name (greatest `updated_at`, then greatest `score_id`). `score` is its `value_num` (null for categorical and text scores), `score_label` its `value_str`, `has_score` is true when such a score exists. Each distinct name compiles to a left join on a latest-score subquery; at most 8 distinct names per filter. `FunctionSchema` gains `in_sql` (spec 05, 09). |
| D98 | SQL results | JSON results are `{columns: [{name, type}], rows: [{column: value}], truncated}`: output column names must be unique; timestamps are RFC 3339 with 9 digits, `Z` for UTC (D64); binary is lowercase hex, maps are objects, NaN and ±inf are null; `type` is the Arrow type as DataFusion prints it. At most 10,000 rows (`limit` 1–10,000, default 10,000), with `truncated: true` when more exist. CSV, NDJSON and Parquet exports stream up to 10M rows and stop there (spec 05, 09). |
| D99 | SQL parameters | Saved queries use `{name:Type}` placeholders, `Type` ∈ `String`, `Int`, `Float`, `Bool`, `Timestamp` (case-insensitive). Values arrive as JSON: string, integer, number, boolean; `Timestamp` takes RFC 3339 or integer epoch milliseconds. A missing, extra or ill-typed parameter is a 400 that names it. They become DataFusion `$n` placeholders before planning (spec 05, 09). |
| D100 | DSL casts | The filter DSL allows `CAST(x AS t)` and `x::t` with `t` one of `BIGINT`, `DOUBLE`, `VARCHAR`, `BOOLEAN`, `TIMESTAMP`. They compile to `TRY_CAST`, so a cast that does not fit skips the row instead of failing the query (spec 05). |
| D101 | SQL time window | `POST /sql` (JSON and exports) and the MCP `query_sql` tool take an optional time window `from`/`to` (RFC 3339, both or neither, `from < to`). `QueryContext::new(source, window)` writes it into the view definitions: `spans` and `traces` keep rows with `start_time ∈ [from, to)`; `scores` keeps rows with `created_at ∈ [from, to)`; `sessions` follows from the windowed `traces`; `experiment_items` and `dataset_items` are not windowed. The SQL console UI always sends its time picker's range. The read endpoints build their context without a window and apply their own (spec 05, 09, 11). |
| D102 | Normalization | **Hybrid normalizer, no convention trait.** An attribute bag records which keys were read and whether they fed a payload (spec 02 rule 2). Scalar fields are precedence tables. Span kind, payloads and time-to-first-token are one function per convention; the first value wins for the whole field (spec 02 § Pipeline, § Convention detection). |
| D103 | Normalization | **Normalization is pure and returns its media.** `normalize` returns spans, media blobs and rejections, and does no I/O. The server stores each blob before the WAL append (spec 02 § Pipeline, § Media extraction). |
| D104 | Pricing | **Built-in prices are a committed snapshot.** `crates/otel/prices/builtin.json` is embedded in the binary and regenerated by `just prices-update`. It is never fetched at build time or at runtime (spec 02 § Cost computation). |
| D105 | Normalization | **The normalizer returns `Vec<Span>`.** The server converts the batch before appending it (spec 02 § Pipeline). |
| D106 | Timestamps | **Out-of-range timestamps reject; a reversed end is clamped.** Nanoseconds above `i64::MAX` reject the span (`timestamp_overflow`). The D85 bounds reject it (`start_time_out_of_range`). `end < start`, including a zero end, sets `end_time = start_time` and records `end_before_start`; the span is kept (spec 02 rules 17 and 21). |
| D107 | Normalization | **AnyValue limits.** Nesting deeper than 32 levels becomes `[llmobs: max depth]` and the attribute is listed in `truncated`. In one key-value list the last duplicate wins. There is no attribute-count cap (spec 02 rule 19). |
| D108 | Ingestion | **OTLP/JSON is the standard encoding.** Integer enums, hex IDs, and int64 as a decimal string or a number. Enum names fail decoding (400). Unknown fields are ignored by `opentelemetry-proto` 0.33.1 `with-serde`. ID length is checked per span (spec 02 § Endpoints, rule 15). |
| D109 | Cost | **Reported cost is never mixed with the price table.** Any reported-cost key sets `cost_source = reported`. Present parts fill their columns; missing parts stay null. `cost_total` is the reported total, else the sum when both parts are present, else null (spec 02 § Cost computation). |
| D110 | Normalization | **Token semantics are declared per source.** Exclusive input or output counts are added back. If `input_tokens < cache_read + cache_write` after that, the cache is added back and `input_excludes_cache` is recorded. Per-modality counts are subsets and stay in `attributes` (spec 02 § Token semantics). |
| D111 | Ingestion | **Rejection reasons are a closed set.** `partial_success.error_message` lists at most 4 reasons with counts, and never a value from the request (spec 02 rule 21). |
| D112 | Testing | **Robustness tests use proptest** in `just test`. There is no cargo-fuzz (spec 02 § Testing). |
| D113 | Normalization | **Multi-source research rows are in spec 02.** Behaviours reported by one source only (Vercel v5 + Anthropic exclusive input, event-based TTFT, OpenLLMetry Anthropic and ADK token semantics) are written as pinned by a captured fixture until B2 captures exist (spec 02). |
| D114 | Mock provider | Responses come from a local mock provider at the HTTP layer. It serves the OpenAI Chat Completions, Responses and Embeddings APIs, Anthropic Messages, and Gemini `generateContent`, `streamGenerateContent` and `embedContent`/`batchEmbedContents`, streaming (SSE) included. Each scenario scripts its turns in a provider-neutral form (text, reasoning, tool calls, finish reason, usage, model, delays). The mock renders the script into each provider's wire format. No API keys, no cost, deterministic, synthetic content only. SDK internals are never patched (spec 02 § Testing). |
| D115 | Capture tool | The harness is a Rust tool, `llmobs-capture`, in `tools/capture`. It is a workspace member that is never shipped. It runs the mock and an OTLP/HTTP receiver on loopback ports, starts the scenario program with a clean environment pointing at both, waits for it, then writes `case.json` and `input.json` through `opentelemetry-proto`'s serde encoding. Scenario programs live in two standalone projects: `tools/capture/py` (uv) and `tools/capture/ts` (pnpm) (spec 02 § Testing). |
| D116 | Capture determinism | Captures are deterministic except for timing. Trace and span IDs are re-minted from the case path in order of appearance. Times are shifted so the first span starts at `ingest_time − 10 s`, keeping real durations rounded to the millisecond, and timestamp-valued attributes get the same shift. The mock's delays are scripted (time to first chunk, delay between chunks), so timings stay stable to a few milliseconds. Machine-specific values are pinned or dropped: `server.address`/`server.port` become the real provider host and 443, `host.name` becomes `capture-host`, and process, OS-version and path attributes are dropped. Instrumentation and SDK versions are kept. A final leak check refuses to write if a loopback address, the mock or receiver port, the home directory, the repository path or the machine's hostname is still present. A recapture of an unchanged scenario differs only in timing values and `captured_at`. |
| D117 | Capture runs | Captures are run by hand, never in CI. `just capture <group>/<case>` records one, `just capture-all` records all of them, and `just check-capture` runs the scenario projects' lint and type checks plus a recapture of every scenario compared with the committed `input.json` (timing excluded). The scenario projects are outside the root pnpm workspace and `just check`, so CI never installs LangChain, ADK or three majors of `ai`. Versions are exact pins, bumped by hand when someone recaptures. Dependabot doesn't watch these projects. The 7-day release-age rule still applies: pnpm `minimumReleaseAge` and uv `exclude-newer = "7 days"`. The Rust crate is a workspace member, so its unit tests run in `just check` and CI like any other crate. |
| D118 | Captured fixtures | A captured case may be committed with only `case.json` and `input.json`. `expected.json` is written in bless mode when the convention's normalization lands, then reviewed line by line. The fixture validation test accepts a missing `expected.json` for `origin: "captured"` cases only. The golden test skips those cases and lists them as awaiting bless (spec 02 § Testing, `fixtures/otlp/README.md` § Workflows). |
| D119 | S3 tests | CI tests the S3 code paths through `object_store`'s `InMemory` store wrapped in a fault-injecting store. An integration test against a real S3-compatible server (Versity Gateway in its doc comment) runs only when `LLMOBS_TEST_S3_ENDPOINT` is set. It is documented in `AGENTS.md` and run locally before merging storage changes that touch object writes. |
| D120 | WAL truncation | A flush deletes a WAL segment only when a later segment exists and `first_seq` of that later segment, minus one, is `<= flushed_seq`. The newest segment stays, because the writer may still be appending to it. Replay skips records at or below `flushed_seq`, so a segment that mixes flushed and unflushed records is safe. The extra data is at most one segment, `wal.segment_bytes` (spec 03 §1). |
| D121 | Capture matrix | Captured cases cover the official OTel GenAI instrumentations (OpenAI v2, Google GenAI); OpenInference and OpenLLMetry for the OpenAI, Anthropic and Gemini clients and for LangChain, LangGraph and the OpenAI Agents SDK, where each has an instrumentation; the Vercel AI SDK v5, v6 and v7; the Langfuse SDK (current major, 5.x, Python); Laminar (Python); Google ADK's native spans and OpenInference's ADK instrumentation. The `llmobs` group is not captured: spec 10's SDK integration tests cover it (spec 02 § Testing). |
| D122 | Capture case policy | A recapture replaces `input.json` and `case.json` in place, and git history keeps the old shapes. A captured `input.json` is never edited by hand: change the scenario and recapture. Each instrumentation × provider gets one non-streaming chat case (with a tool call where the API has one) and one streaming case, plus scenario-specific cases (cache tokens, multimodal input, embeddings, agent runs). Majors are kept side by side only for the Vercel AI SDK. |
| D123 | UI scope | **The UI track builds the pages whose API contract exists.** Traces, spans, the trace view, sessions, users, the dashboard, saved views, the filter bar, the ⌘K palette and live mode. Pages and actions without a contract wait for the track that adds it: the SQL console, datasets, experiments, evaluators and online rules, alerts, settings, API keys, members, login/signup/setup, bulk actions, the annotation form, "run evaluator on this trace", and GDPR deletion (spec 11). |
| D124 | UI layout | **A thin top bar and a collapsible left sidebar.** The bar has the product name, the org/project switcher, ⌘K, the theme toggle and the user menu. The sidebar lists only pages that exist, collapses to icons, and stores that state in localStorage (spec 11). |
| D125 | Trace view | **A trace opens in a resizable split beside the list.** A row sets `?trace=<id>`; the list keeps its scroll and selection. j/k or ↑/↓ move between rows and the open trace follows; Esc closes the split. The ratio is in localStorage. The same view is a full page at `/:org/:project/traces/:traceId`. The span tree and the span detail are a second resizable split. There is no drawer and no modal (spec 11). |
| D126 | Trace view | **The span tree and the timeline are one combined grid.** Each virtualized row has an indented name, a kind icon and status, right-aligned duration, tokens and cost, and a bar on a shared time axis. A Transcript toggle shows the trace's LLM and tool spans as one conversation. The combined grid is the default; the mode is in the URL (`mode=transcript`) (spec 11). |
| D127 | UI tokens | **Dense type, mono for IDs and numbers, dark by default.** Inter for text and JetBrains Mono for IDs, numbers, JSON and code. Base text is 13 px. Table rows are a fixed 28 px, single-line, truncated, full text on hover. Light and system stay selectable. Status and span-kind colours are tokens. No external network calls (spec 11). |
| D128 | Charts | **Charts use Recharts through shadcn's `chart` component.** Recharts loads only with the dashboard route. Empty buckets are gaps for rates and percentiles (spec 11). |
| D129 | Filter bar | **In the filter bar, the text is the truth.** One single-line CodeMirror editor holds the DSL (spec 05). A client parser splits top-level `AND` conjuncts and recognises simple shapes (`column op literal`, `IS [NOT] NULL`, `[NOT] IN (…)`, `@>`, `score('n') op x`, `has_score('n')`) as editable chips. Everything else is a raw chip. The server validates: a `400 invalid_filter` underlines the position and shows the message. A broken filter is never applied silently. Autocomplete comes from `GET /schema`. There is no facet sidebar yet (spec 11, 05). |
| D130 | Times | **Times are local by default.** "Show times in UTC" lives in the user menu and in localStorage. The tooltip and the clipboard copy are the full RFC 3339 string with nanoseconds (spec 11). |
| D131 | UI mocks | **Volume comes from a seeded generator, not from the fixtures.** `fixtures/api/` stays the small contract-checked set. `web/src/mocks/generated/` produces thousands of traces and one 10 000-span trace, typed by `schema.gen.ts`. `just web-dev` switches to it with `?mock=large`; tests use it through `server.use`. Saved views get stateful in-memory handlers (spec 11). |
| D132 | UI tests | **UI tests are Vitest and Testing Library only** (D74). Page tests run on the MSW mocks with `server.use` and never mock modules. Pure modules get unit tests. Quality-bar targets are bounded rendered-row counts and pure-function tests on 10 000 spans, not timings. There is no Playwright (spec 11). |
| D133 | UI lists | **Traces and spans are separate pages.** Each row is one trace or one span, with the same table and filter bar. There is no spans-first default (spec 11). |
| D134 | Live mode | **Live mode uses `EventSource`.** It subscribes to `/traces/stream` and `/traces/{id}/stream` (spec 09 § SSE), mocked with MSW's `sse()` (spec 11). |
| D152 | Trace merge operator | Spec 01's trace merge is implemented once, in Rust, in `llmobs-storage`. It builds partials at flush, builds memtable partials at query time, merges partials in queries, and serves compaction. It replaces a SQL `GROUP BY trace_id`, whose ordered `first_value` and list-union aggregates cost several microseconds per trace in the trace-list benchmark. The `traces` provider accepts every filter as exact. `start_time` ranges and `trace_id` equality also prune the partial scan, and every filter is evaluated on merged rows. Only the columns a query needs are merged (spec 03 §6). |
| D153 | Trace list fast path | `Storage::query` hands A2's session a physical optimizer rule (`ProjectQuery.optimizer_rules`). It recognises `ORDER BY start_time DESC, trace_id DESC LIMIT k` over the `traces` scan, through projections, including A2's hex-encoded `trace_id`. The scan then reads disjoint slices back from the newest time (15 min, 1 h, 6 h, 24 h, the rest). In each slice it ranks traces on the columns the filter needs, and stops once `k` traces match. Then it fully merges only those `k`, each within its own slice's window. Other sorts, and filters that DataFusion keeps above the scan (score functions), use the full merge (spec 03 §6). |
| D154 | Lookup hint | `Storage::query(project, QueryOptions { around })`. With `around`, a `trace_id` lookup without a time range reads only the `spans` and `traces` files that overlap `around ± 1 day`. Without it, statistics and bloom filters prune across all of the project's files (spec 03 §6). |
| D155 | Evaluation library | `llmobs-eval` (`crates/eval`) runs one evaluator — checks, mapping, templates, judges, webhooks and the judge trace — and returns a score value plus normalized spans. It depends only on `llmobs-core` and `llmobs-otel`; the server track owns the queue, tables, encryption and handlers (spec 06). |
| D156 | Evaluation storage | Secret encryption (`LLMOBS_ENCRYPTION_KEY`, AES-256-GCM with AAD `table:column:row_id`), `instance_settings`, `llm_connections`, `evaluators`, `online_rules` and `rotate-encryption-key` move to the Wave 2 eval server track. The library receives decrypted values and never stores them, which supersedes D135 (spec 04, 06). |
| D157 | Judge structured output | Each LLM connection has `structured_output`: `native` (default), `tool` or `prompt`, with no automatic downgrade. `native` is OpenAI `json_schema` strict, Anthropic `output_config.format` and Gemini `responseJsonSchema`; `tool` is a forced tool call; `prompt` appends the schema. A rejected mode is a permanent error that names the setting (spec 06, 04). |
| D158 | Judge answer | The schema is `explanation` (only when `include_reason`) then `value` or `label`, every property required, no numeric bounds. The parser accepts a tool call, one JSON object, a markdown fence or the first JSON object, and the explanation becomes the score's `reason`. The field is never named `reasoning` (spec 06). |
| D159 | Judge requests | Judges call OpenAI Chat Completions with `max_completion_tokens`, Anthropic Messages with `max_tokens`, or Gemini `generateContent`, as one user message. `temperature` is unset by default, `max_output_tokens` defaults to 1024, timeouts are 10 s to connect and 60 s for the call (at most 300 s), and a response over 4 MiB is an error (spec 06). |
| D160 | Evaluator errors | A judge or webhook run makes one HTTP call. Timeouts, connection errors, 408, 425, 429 and 5xx are retryable; 401, 402, 404, quota exhaustion and a 403 that is not a content filter pause the rule; other 4xx, bad answers, refusals, content filters, missing variables and a rejected mode are permanent. The queue applies backoff and pause, and error text never contains the prompt or the answer (spec 06). |
| D161 | Judge traces | Every evaluator run is built as OTLP and passed through `normalize`, so previews, truncation, media and cost match SDK spans. The caller supplies the trace id, span ids are the first 8 bytes of SHA-256 of the trace id and the span index, and `judge.cost_usd` is the `llm` span's cost. An external `environment = "llmobs-eval"` is rewritten by the OTLP handler after normalization, not by `normalize` (spec 06, 02). |
| D162 | Mapping expressions | Expressions are `trace.*`, `span.*`, `span[name=…]`, `span[kind=…]`, `expected` and `item.*`, plus an optional JSONPath and a trailing `?`. The root is the parentless span (the earliest if several), otherwise the first `llm` span; JSONPath yields absent, one value, or an array (spec 06). |
| D163 | Prompt templating | Templates use minijinja with strict undefined, no auto-escaping, a fuel limit of 100 000 and a 64 KiB limit. Strings render as themselves, messages as `role: text` lines, other JSON as compact JSON, and `trace.transcript` as an indented tree capped at 2 000 characters per payload and 60 000 overall (spec 06). |
| D164 | Check semantics | Text comes from a string, the last assistant message, or compact JSON. Defaults are a case-sensitive trimmed exact match, case-insensitive `contains` in `any` mode, a Rust regex with a 1 MiB size limit, Draft 2020-12 JSON Schema whose reason is the first error's path and keyword, and normalized Levenshtein `1 − distance / max(len)` (spec 06). |
| D165 | Webhook evaluator | The webhook is a POST with the spec 06 body and an HMAC `X-Llmobs-Signature`, a default timeout of 10 s (at most 60 s), no redirects and a 64 KiB response cap. A 200 whose JSON fits the output definition is a score; any other status follows D160, and a 200 with a bad body is permanent (spec 06). |
| D166 | Egress SSRF guard | Judges and webhooks share one rustls client that follows no redirects and drops every resolved or literal address in a denied range unless `allow_private_network_egress` is set. Denied ranges are loopback, RFC 1918, CGNAT `100.64.0.0/10`, link-local, unique local `fc00::/7`, unspecified, multicast, broadcast, `192.0.0.0/24`, `198.18.0.0/15`, documentation ranges, and their IPv4-mapped and NAT64 forms (spec 12). |
| D167 | Live provider tests | CI never calls a real provider. Integration tests use an in-process mock; live tests are ignored and run only through `just eval-live` (E19). |
